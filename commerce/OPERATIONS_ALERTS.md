# 出单、履约、库存提醒与经营组合

更新：2026-11-11（Asia/Shanghai）。首家真实接入目标已确定为 **Ozon 俄罗斯**，履约方式由用户稍后补充。本页功能已实现本地核对资料与演示流程；Ozon 实时订单/库存同步和飞书推送仍待接入。

## 从工作台使用

打开 **提醒与经营**：

- **出单与补货提醒**：先选择资料范围。默认“手工资料 · 未连接平台”，无资料时显示未知状态。可点击“载入演示订单与库存”试用，演示记录独立保存。
- **记录订单**：填写店铺、仓库、SKU、状态、数量、实际核对时间和来源链接/文件行号/截图索引。原始订单截止时间未知时留空，不按统一天数猜测。
- **记录库存**：填写可售库存、实际销量窗口、交期、安全天数、整箱件数及在途。没有在途须明确填 0，空白表示未知。多店铺、多仓库、SKU 独立计算。
- **标为已阅**：只记录已阅读，不代表已经备货、发货、下采购单或补齐库存。
- **导出提醒与来源证据**：保留原始观察、SHA-256、规则、提醒及状态历史。可在折叠区下载标准 JSON 模板或分批导入，最多 50 条/批；它不是 Ozon 原始 CSV 列格式。
- **投流与促销组合**：先在“运营测算 → 成本测算”填写成本，回来填写两种方案的售价、商家优惠、每单广告、达人佣金和目标贡献，比较结果并导出依据。演示组合只填样例方案，成本仍沿用成本测算中的资料。

## 已实现的提醒规则

| 触发 | 行为 | 限制 |
| --- | --- | --- |
| 首次观察到待处理订单 | 提示新增待处理记录，附店铺/仓库/SKU/来源 | 不冒充刚刚成交的实时推送 |
| 待备货、待发货 | 按明确状态提示，使用来源中的发货截止时间 | Ozon FBO 不生成商家待打包提醒；履约未知时只提示待确认 |
| 临近截止、超过截止 | 根据明确截止时间与本地预警规则计算 | 缺截止时间保持未知；没有修改订单状态 |
| 库存覆盖不足 | 展示记录时覆盖、在途扣减和整箱补货草稿 | 销量、交期或在途未知时不生成确定补货量 |
| 在途时间无法抵消缺口 | 提示核对，保留到货假设 | 仅当 ETA 仍在未来、早于预计断货且在规划期内才扣减；过了 ETA 没有收货记录，不能视为已到货 |
| 库存覆盖较长 | 提示复核积压与组合方案 | 不从单一窗口断言滞销 |
| 数据过期 | 挂起原提醒，提示重新核对/同步 | 不将陈旧数据解释为库存正常或问题已解决；已完成/已取消订单不反复追催 |

本地默认值为资料有效 60 分钟、截止前 24 小时提醒、覆盖 90 天触发积压复核，可在界面调整。这些不是平台承诺或平台期限。成本和补货结果都是基于输入的估算，来源尚未独立核实。

服务运行时每 60 秒检查已存资料，打开提醒页时也会重新计算。Mac 休眠、断电和服务停机期间不能保证及时提醒。当前仅在工作台展示，不向飞书、手机或客户发送消息。并未安装聊天提醒自动化或通知网关。

## 去重与状态证据

相同范围、相同事件 ID 和相同内容重复导入不重复写入；内容改变但复用相同 ID 会拒绝。店铺、市场、仓库、记录类型、订单/SKU 构成业务范围。同时间不同内容要求核对后使用新的实际观察时间，较旧记录只留档。

后续取消、完成或已发货记录可关闭原提醒。数据过期将风险提醒挂起，恢复新鲜数据后重新评估；已阅提醒在级别升级时重新提示。每次创建、更新、已阅、挂起和关闭保留事件哈希与时间。哈希说明内容的一致性，不能证明卖家后台陈述真实；本地账本也不是防篡改审计服务。

## 组合测算口径

```text
优惠后收入 = 售价 - 商家承担优惠
广告前单件贡献 = 优惠后收入 - 明确填写的采购/物流/固定费用
                 - 按优惠后收入计算的平台/支付/退货预留 - 达人佣金
广告后单件贡献 = 广告前单件贡献 - 每单分摊广告费
达到目标时的每单广告空间 = 广告前单件贡献 - 目标单件贡献
```

所有金额同币种，不自动换汇；每项费用保留两位小数。各方案单独计算广告金额，不再重复扣成本表中的广告比例。平台承担的补贴不当成商家优惠再次扣除。费用基数是明确的简化假设，须按实际站点账单核对；未填的税费、固定成本和退货差异不自动补齐，结果不能称作净利润。

库存充足、紧张、积压或未知目前由用户人工核对选择，尚未自动将 SKU 成本、库存和广告归因关联。未知库存时提示核实；紧张库存时优先提示补货和收缩扩量，即使计算贡献为正。没有自动调价、参加促销或改广告预算。

## Ozon 接入准备与官方依据

当前缺少履约模式、店铺只读 API 凭据、接口样本验证和飞书接收配置。没有调用真实 Ozon 店铺，也没有把手工记录作为已授权 API 数据。

核对来源为 [Ozon 官方旧订单接口停用公告](https://dev.ozon.ru/news/734-Otkliuchenie-starykh-metodov-Seller-API-dlia-raboty-s-postingami/)，正文发布日期 2026-06-01，本轮核对日期 2026-11-11：

| 来源原文/字段 | 中文记录 | 使用边界 |
| --- | --- | --- |
| Новая дата отключения: 1 августа 2026 года. | 公告将旧接口的停用日期调整为 2026-08-01 | 是官方公告记载，未用真实账号再次测试旧接口状态 |
| `/v3/posting/fbo/list` | 公告列出的 FBO 新版订单列表方法 | FBO 实店返回结构、分页和权限待验收 |
| `/v4/posting/fbs/list`、`/v4/posting/fbs/unfulfilled/list` | 公告列出的 FBS 新版订单列表/未完成订单方法 | FBS / realFBS 的实际适用方式须按店铺确认 |

不采用许多旧示例仍在使用的 `/v2/posting/fbo/list` 与 `/v3/posting/fbs/list` 作为当前接入方案。库存字段、可售/预留定义、分页、时区、取消与退款状态映射、限流、断连和消息送达回执都须在真实接入时验证。客户姓名、电话和地址不是出单提醒必需内容，不纳入本地观察模板。
