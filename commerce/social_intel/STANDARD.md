# 社交信息记录与阅读标准 v1

适用：X、TikTok 的公开帖子、视频与搜索样本，以及明确标记的官网补充资料。沿用上级 `RESEARCH_STANDARD.md`，补充采集证据、阅读和跨工具交换。本目录已实现离线校验、私有持久化、9个共享 MCP/HTTP 工具，并接入工作台「全球情报 → 社交观察」。验收范围见 `../qa/READING_WORKSPACE.md`。接入成功不表示手机平台访问或来源真实性已经解决。

## 阅读与排序

工作台「信息聚合」增加「社交观察」视图，复用当前列表与详情组件。三个主题为电商选品与市场趋势、AI 工具与自动化、行业新闻与热点；默认每类精选 TOP 3。TOP 指本次检索样本，不是平台全站排行榜。显示检索词、采集范围、候选数、入选数及不足原因。未知国家不在地图中猜测定位。

列表每项展示中文标题、两句摘要、来源、原始发布时间、实际采集时间、内容性质和入选理由。点赞/播放/销量分列，不互相换算；不把累计点赞当增长趋势。点击后中栏阅读，右侧查看证据；窄屏改为顺序阅读，不截断正文。只读资料与业务待办分开。

详情顺序：中文摘要 → 原文短摘录及定位 → 为什么值得看（判断）→ 限制/冲突 → 建议下一步（判断）→ 原始链接 → 采集证据 → 历史时间线。原文、译文、摘要、判断分别存储；译文记录方法、复核状态与原文哈希。无字幕/音频转写时不能宣称读完视频。

TOP 入选须有可打开核对的单条原始链接、原文摘录、证据文件和采集时间，且不是失败记录。X 只接受匹配官方域名的 status 路径；TikTok 只接受匹配官方域名的 video/photo 路径，短链接须先解决出处，不得自报为单条原始链接。官网补充接受非首页的 HTTPS 原始文章链接，并在列表显示「网页补充」与主机名。缺少链接的结果进入「待补来源」，不占用正式 TOP 名额。已有观察到的单条链接、但尚未入选的记录显示「候选 · 待核实」；不能把未入选等同于来源缺失。界面筛选「候选（未入 TOP）」沿用 API 的 `view=pending`，范围是全部未入选记录。AI 生成素材、广告、旧资料、未独立核实、仅搜索摘要都须直接标出。热点需按实际发布时间筛选，时间不明不能冒充今天新闻。

排序 v1 为人工逐项说明的研究优先级；保存 `rank`、`reason`、`basis`。不伪造精确评分。后续自动排名须冻结候选集合、查询上下文、规则版本和每项分量，才能重现。互动量仅是关注信号。产品可采购、工具可用、新闻属实各需独立核验。

## 统一数据包

主格式为 UTF-8 JSON，`schema=commerce-social-intelligence-v1`。JSONL 为同一数据包的逐条传输视图，Markdown 为只读阅读视图。三者的 `record_id` 与 `content_sha256` 保持一致。CSV 只作扁平索引，不能取代带证据和历史的主包。源站可变，原始 URL 与实际观察截图必须同时保留。

数据包包含：`batch_id / created_at / scope / records / record_versions / assets / attempts / events`。`records` 为最新记录，`record_versions` 为实际保留的旧记录；`scope` 保留主题、目标名额、关键词和排序规则；不得把关键词搜索结果视为代表性抽样。

每条记录包含：

| 字段 | 口径 |
| --- | --- |
| `record_id` | 不随摘要或互动数变化的本地稳定 ID；缺少平台 ID 时分配 provisional ID，后续关联时保留别名，不能重写历史 |
| `category / title_zh / summary_zh` | 主题、可读标题和中文摘要 |
| `source` | 平台、原始链接、链接类型、来源可访问状态；搜索页/主页不能伪装单条链接 |
| `published` | 原始显示文本、可确认的 ISO 时间或 null、精度；“7-24”不得猜年份 |
| `captured_at` | 实际读取时间，含时区；不得用写报告时间冒充采集时间 |
| `original / translation` | 原文短摘录、定位、摘录方式；中文翻译、方法、原文哈希、复核状态 |
| `metrics` | 指标名、屏幕原始显示值、可确认值或 null、观察时间；缩写量为近似值，不标成精确统计 |
| `verification / limitations` | 观察到界面、独立佐证、冲突、未知分开；没有证据保持未知 |
| `ranking` | 是否入选、名次或 null、理由、规则版本、冻结依据哈希 |
| `evidence_ids` | 关联全局 `assets` 中的文件相对路径、SHA-256、类型、采集时间、字段/界面定位；文件路径必须以 `evidence/` 开头 |
| `content_sha256` | 内容核心的 canonical JSON 哈希；不包含互动指标、采集时间与阅读状态 |
| `record_sha256` | 包含摘要、翻译、指标和证据引用的完整记录哈希；事件同时绑定该哈希以准确引用衍生版本 |

`attempts` 记录成功/空结果/受阻的尝试及证据，采集失败不生成假内容，也不删除旧成功资料。`events` 是只追加的过程日志，绑定记录 ID、内容版本、事件时间、动作、结果和证据 ID。历史只覆盖实际观察以来的过程，不能回填未采集历史；本地文件及其哈希不是防篡改审计系统。网页读取工具可能使用缓存；必须标出摘录记录与完整网页快照的区别，批量读取保存实际回执时间窗口，不用写报告时间冒充抓取时间。

## 版本、存储与导出

来源内容变化产生新内容版本；互动指标变化新增 observation，不制造正文更新。翻译/摘要修改保留衍生版本与所依据的内容哈希。已读绑定内容版本；收藏跟随稳定 ID；已读、收藏、选入 TOP 不改变核实状态。外部工具创建核查任务时必须带 `record_id + content_sha256 + idempotency_key`；旧版本冲突返回错误。

现已独立使用 `social_batches / social_heads / social_versions / social_receipts / social_marks / social_reviews`，证据保存在私有 `social/batches/`。批次 ID 与内容绑定，不可覆盖；重传按幂等键核对同一内容。旧记录更新必须明确提供 `expected_heads`，否则拒绝。旧完整记录、源证据及批次事件继续保留。没有直接写入既有 `intel_items`：其 `CONTENT_KEYS` 不覆盖社交原文、翻译、指标和媒体证据。旧 `commerce-intel-evidence-v1` 保持不变，不把新包伪装成已支持的旧格式。

正式 TOP 读取最近一个包含入选记录的冻结批次，不把所有历史 TOP 叠加成新榜。打开记录时带精确记录版本；若已出现更新，历史版本仍可阅读，新核查待办须以当前已展示版本创建。分页绑定筛选及结果版本，变化后回到第一页。

私有状态存于现有工作台状态目录；证据目录和文件权限分别为 0700/0600。原始截图、设备配置和运行日志不放入公开源码。默认跨工具传 JSON 及授权后的相对证据索引；导出前审阅图片和摘录，去除账号/设备/本机路径与无关个人信息。证据路径不允许绝对路径、目录穿越或越出包根目录的软链接。跨机器按证据 hash 寻址，不能把本机绝对路径当通用 URI。

社交模块当前保留已导入历史，没有启用90天自动清理；后续归档须保留核查/任务引用，避免断链。引用来源的内容始终是资料，不是对 Codex、Hermes 或 Harness 的执行指令。

## 接口与适配计划

共用接口已注册，浏览器、Harness、Codex、Hermes 共享同一权威数据和版本。旧会话需要重新发现工具表；不会改写客户端配置来制造工具已更新的状态。

| 工具 | 行为 |
| --- | --- |
| `commerce_social_stage` | 暂存主包，返回 stage ID、证据 ID 和已接收偏移 |
| `commerce_social_upload` | 证据按 ID 和字节偏移分片上传；相同分片重传校对原字节 |
| `commerce_social_commit` | 检查文件、哈希、来源与旧版本，再原子导入并保存回执 |
| `commerce_social_search` | 主题、关键词、当前精选、未入选候选、收藏、未读筛选 |
| `commerce_social_get` | 当前或明确历史版本、事件、证据索引；不自动核实 |
| `commerce_social_mark` | 版本绑定的已读/未读与稳定 ID 收藏 |
| `commerce_social_asset_read` | 按登记批次与证据 ID 分片读取，不接收文件路径 |
| `commerce_social_export` | JSON、完整交换 JSONL 或 Markdown；证据按 ID 另取 |
| `commerce_social_review` | 精确版本的本地核查待办；跨客户端键复用同一版本任务 |

跨客户端统一限制：主包元数据 UTF-8 最多100,000字节；二进制分片最多90,000字节，base64最多120,000字符；单文件最多16 MiB、每批证据合计64 MiB。这样保留既有 Harness 128 KiB 请求上限，不改变桥接协议。离线导出另有上限，不代表宿主能一次接收同样大小的主包。断线后先读取 stage 回执偏移；不自动创建另一批未知写入。

Obsidian 可读取 Markdown 与 JSON 链接；表格软件读离线导出的索引 CSV；自动化工具读 JSON/JSONL；均回传稳定 ID、版本和回执。当前模块不把完整采集内容写入永久记忆。

界面接入只改 `web/intel-ui.js / .css` 源文件，并复用 `ui/kit.js / primitives.css / tokens.json`；构建生成 app.js/style.css 的标记区域。原文用文本节点，链接只允许 HTTPS/HTTP，禁止渲染采集来的 HTML/脚本。保持浅色、深色、跟随系统，黑灰深色基调，以及现有三资源内联桥接协议。

已验证：真实 stdio MCP、幂等与版本冲突、证据哈希、浏览器与已安装 Harness 宿主组件的隔离原生桥接、390px 窄屏、三种主题及键盘焦点。此模块没有新增弹窗。实际手机访问缺项、独立事实核验、平台接口权限、其它宿主版本和公开发布仍须分别验收。

## 本目录使用

`python3 commerce/social_intel/package.py INPUT.json --output PRIVATE_DIRECTORY` 校验记录、哈希和证据文件，生成规范 JSON、JSONL、Markdown 与单文件阅读样张。读取界面复用共享 UI，但不导入生产数据库、不调用平台、不修改客户端配置。真实样本保存在私有目录；测试只使用合成内容。

`python3 commerce/social_intel/import_package.py INPUT.json` 通过运行中的共享 HTTP 接口暂存、上传和导入已审阅的私有包。更新已有记录时必须提供 `--expected-heads HEADS.json`；该文件是已展示记录 ID 到记录 SHA-256 的映射。该命令不会重启服务或操作真实平台。浏览器支持 `/#social` 直接进入社交观察，沿用既有本机认证。
