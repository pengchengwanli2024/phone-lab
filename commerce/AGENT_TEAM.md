# 运营角色与执行层设计

`agents/roles.json` 和 `agents/SOUL.md` 定义运营总控、平台运营、库存履约、客服售后与技术值班五类职责。角色配置不表示模型进程、渠道网关或真实店铺已上线。

所有入口使用同一个后台与任务 ID。目标是在后续执行层持久化追问、确认、执行结果及通知状态；当前核心仅实现任务排队与取消。

- 缺少关键信息时，问一个最能改变决策的问题，并推进不依赖答案的工作。
- 确认应绑定具体任务、参数、范围和有效期。参数变化后不能沿用原确认。
- 外部回执不确定时保留 unknown，核对前不重复执行。
- 平台写操作需要单独实现适配器和授权；角色文本不能代替权限校验。
- 状态通知只使用足够新鲜且已授权的数据，合并重复消息，保留失败记录。

Hermes 可使用独立 `commerce-bot` profile 接入共享 MCP，避免复制现有模型、账户和渠道配置。飞书、企业微信等入口仍需官方应用接入、范围配置及实际收发验证；本仓库没有可用的渠道凭据或已启动网关。

本机 launchd 监督不等于全天候在线。后续服务器部署需要验收重启恢复、离线补偿、取消、幂等、确认过期和恢复后的状态一致性。
