## 操作顺序

1. 按平台、方向、关键词或接入状态检索，查看完整技能流程与引用。
2. 阅读相关references，补齐本次任务输入；涉及当期规则、费率、资格时核对官方资料。
3. 如有细分模式，先明确选择模式并按需生成字段模板。模板列出各路线的键，不表示全部都属于第一步。准备时保存模式哈希、具体流程、各工具待补字段、本工作台注册表检查及时间；字段存在不证明有效性，工具已登记不证明账户权限。
4. 准备任务，保存固定来源和输入。非离线脚本技能可先填入分析任务模板、补齐证据，再明确请求生成草稿。相关工作台工具提示只是部分相似能力，不作为上游技能的替代验收。
5. 对已接入的计算器，显式执行。缺数据保持HOLD，未知不补零。任务只执行一次；重启中断保持中断状态，同一任务不会自动重跑。
6. 核对回执与结果适用范围。所有19项均为本地处理，不提交广告、Listing、索赔、采购或消息。

类型由标题规则自动归纳，仍需领域复核。每项同时保留原技能要求，并将完整SKILL.md和选中的配套参考送入模型；共同章节并不替代原始交付条件。一次最多7个文件、48000字符，按完整文件选取，未纳入文件逐一列出；所选细分模式的流程文件不能被静默省略。

任务输入采用 `goal / scope / facts / parameters`。每条事实包含 `id`（F1等）、`text`、`source_ref` 和 `label`（provided、synthetic、estimate或unknown）。最低输入检查只核范围和有来源的依据，**不代表已校验每项原始业务字段**；额外缺项由模型明确列出，再由业务审阅。unknown资料不作为已知事实。

模型调用复用现有路由，不修改模型配置。每次仅一条受限请求，工具列表为空，不提供账户操作、任意脚本或文件读取能力。任务来源、契约、输入和执行程序版本被冻结；未知、超时、中断不自动重发。模型结果检查章节、类型和引用ID：F为调用者资料，K为技能方法；方法引用不能冒充商品事实。数值漂移会提示复核，引用可解析也不证明事实正确。

工作台支持生成、状态查询、请求取消、查看依据及参考范围、私有JSON/Markdown导出，以及绑定结果哈希的调用者审阅。编辑输入或模式会清除旧任务显示，晚到的响应不能覆盖新输入。接受草稿只是调用者审阅记录，不是经营授权或独立验收。

契约v2补上了原文输入和交付要求对照：修复451项“开始前要拿到”标题未被输入摘录识别的问题，上一轮保留的73项在本轮按来源与模式分别补齐，见下文。每条候选要求保持原始ID；新草稿必须逐条说明覆盖状态、调用者依据及草稿章节，漏项和无效引用会被拒收。方法引用可以解释要求，但不能独立证明输入充分；模型自评仍待业务审阅。索引已补充登记的输入参考与模式指南，其他参考分支仍需按具体任务核对。v1历史结果不重写，旧契约不按新版本接受审阅，也不自动重发。

本轮全部778项来源上下文、最低输入门槛和227个模式流程均通过本地检查；8种类型分别使用合成数据调用了真实既有模型，均返回带引用与补充问题的needs_inputs草稿。**8个样例不代表778项语义或经营结果全部通过。** 原文中需实时检索、账户连接、媒体生成或外部变更的步骤仍未由通用文本执行器实现。创意入口本轮交付文字简报，没有在此生成图片或视频文件。MPstats、Amazon Ads、SP-API、AMC/Data Kiosk等账户资格和真实数据不由导入技能自动获得。

上一轮记录见[草稿入口验证](../../verification/sealeap-workflows-result.md)，其中两条采集调度失败作为历史证据保留。前一轮方法深化后，全项目本机回归303条通过，含40条技能模块测试；四条真实模型合成创意样例完成32项原始要求对照，均保留needs_inputs。首轮引用检查失败及修正后独立样例分别保留。实际结果见[方法深化验证](../../verification/sealeap-methodology-result.md)；本地通过不表示正式业务验收、全项目脱敏或公开发布。

## 本轮73项输入来源补齐

[INPUT_RESOLUTION.csv](INPUT_RESOLUTION.csv) 逐项列出上一轮73项的真实定位结果：[INPUTS.md](INPUTS.md) 说明使用和剩余边界。35项找到共同输入来源，38项必须先选择模式；227个模式指南保持各自输入与交付。模式未选择时在本机停止，不请求模型。依赖的输入参考必须进入上下文，不能静默省略；原文行号与哈希随任务保留。

新增输入来源修订通过契约哈希及input_source_revision区分，传输结构仍使用既有v2协议，保留并行会话的模型调用前预检。旧结果不重写、不自动重发。原文索引改为共享按钮显式展开与收起，支持键盘及aria状态。

本轮全项目本机回归355条通过，含52条技能测试。四条真实模型合成样例对照30项原文要求并保持needs_inputs；模式隔离、未选模式门槛、导出、浏览器/iframe和MCP已验证。正式领域、媒体成品、账户及经营验收仍独立保留。具体记录见本地[输入补齐验证](../../verification/sealeap-inputs73-result.md)。

## 固定来源与可复现准备

原仓库快照保留在被忽略的 `.local/sealeap-sources/ecommerce` 和 `amazon`。若源码复制到新环境，先克隆两个上游，再checkout上述提交，然后运行：

```sh
python3 commerce/sealeap_ingest.py
python3 commerce/skills_ui_build.py
python3 commerce/skills_ui_build.py --check
python3 commerce/ui/build.py --check
python3 -m unittest discover -s commerce/qa -p test_sealeap_library.py
python3 -m unittest discover -s commerce/qa -p test_sealeap_drafts.py
```

导入器逐个检查技能名称、文件类型与大小、软链接、固定提交、许可和脚本白名单，不自动拉取更新。更换上游版本需要重新审查、重建和验证；包、脚本或执行参数变化会撤销旧回执的匹配。

素材、配置、输入、计算结果、数据库、验证日志和截图保留在私有状态目录。两个项目的MIT许可、NOTICE及上游第三方声明保留在本目录；未复制其标识、媒体、课程原件或账户资料。有限文本检查不代表全项目完成开源脱敏或已发布。
