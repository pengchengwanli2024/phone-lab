# 岗位、产物契约与实际门禁

本模块吸收用户提供的外部项目经验：岗位能力包、可复验的产物交接、附责任和复验方法的阻断。外部项目的 SKU、毛利、闭环率和因果解释没有作为本项目事实导入，也未读取其文件或执行其 cron / 图片交付建议。

`org.json` 是本模块唯一岗位和依赖契约。12 张角色卡及兼容的 `agents/roles.json` 由 `build.py` 生成。岗位不设层级，没有批准权；阻断必须写明缺什么、谁补、补完如何验。原有五类角色 ID 保留为兼容别名。配置岗位不等于运行了 12 个模型；本轮实现的是实际数据检查、本地产物交付与派单，不是无限自主代理。

## 使用

刷新电商工作台，进入「岗位与闭环」。从已保存库存建立工作项，按产品 ID、SKU、市场和履约范围分别追踪。币种初始保持未知，必须明确指定，不从金额字段名猜测。飞书按用户安排稍后配置，不属于本轮强制门禁，也没有新增定时任务。

```bash
python3 commerce/organization/run.py import-inventory
python3 commerce/organization/run.py
python3 commerce/organization/run.py gaps
python3 commerce/organization/run.py brief creative
python3 commerce/organization/run.py check S6
```

默认 `board` 保存本机私有 JSON、Markdown 和 HTML 快照；读检查、读简报不会自动派单。可用 `--case` 指定工作项。CLI 仅访问同一个本机共享服务，没有广告、发货、改价、采购、消息发送或 cron 安装命令。

## 产物和失败路由

新选品还没有平台商品 ID 时，可先创建明确的本地候选。它只沿用所选现有工作项的连接、市场与履约范围，不复制其 SKU、库存、成本、销量或图片：

```bash
python3 commerce/organization_candidates.py --key home-candidate --name '厨房收纳架（候选）' --source-ref 'local:research-note'
```

可用 `--anchor-case` 明确已有工作项，`--currency` 明确计划币种。建档入口只写当前私有数据库的候选身份，随后通过运行中的共享服务读回；不初始化服务、启动工作器或修改平台库存。相同键重复提交去重，来源或身份冲突会拒绝覆盖。候选在工作台和产物绑定选择器中标为「尚未绑定店铺商品」，真实商品映射、事实及币种转换须另行核对；不能直接拿候选行计算可售库存。

- `S0` 检查本机数据库与契约；不把本机在线当作卖家 API 已在线。
- `S1/S5` 复用已有采集模板，保存原文、中文、来源、校对状态及工作项绑定。检查通过只是资料完整性通过，不能证明来源真实。
- `S3` 先收集明确币种的采购成本、交期和来源，之后 `S2` 才按同一币种、同一采购成本测算贡献。缺项 HOLD，币种错配或贡献不为正保留实测异常；不代替用户决定定价。
- `S4` 将创意工作室已登记的图片复制到私有 `outbox/listing/<case>/<version>/`，保存清单，读取交付目录复验文件哈希及创意版本。其他目录有图不能算交付；图片完整性不等于平台数量、尺寸、使用权或商品事实合格。
- `S8` 检查同一产品和履约范围的订单、库存快照及已核对口径；不等于已实际发货。
- `S6/S7/S9/S10` 尚无独立合规、广告归因、真实客户来源或结算适配器时明确阻断。不虚构零消耗、零差评、合规通过或已对账。
- `S11` 验证上轮快照哈希并比较本轮门禁。保存快照不等于经验已经证明有效，更不会自动修改模型或永久记忆。

FAIL 表示实测不符；BLOCKED 表示能力、接入或上游产物不可用；HOLD 表示资料缺失、陈旧或待核实。下游阶段仍可独立补资料。创建补齐任务按当前证据去重，任务被手工标为完成不能关闭门禁；必须重新读取并验证产物。

看板显示的是「门禁通过率」，分母为 12 个阶段。它不代表经营闭环率、转化率、利润增长、法律判断或来源事实已经独立核实。

## 验证与边界

组织门禁聚合函数经过四个隔离工作空间的同一合成探针及独立状态组合验证，保留通过的原始实现；没有观察到可证明的通用增益。业务层另外验证工作项隔离、币种/成本匹配、图集实际交付、篡改与版本变化、任务不冒充闭环、私有快照和原生 MCP。GUI 复用统一组件及原有三文件内联协议。

契约或角色卡变更后运行 `python3 commerce/organization/build.py` 与 `--check`；界面仍由既有统一构建分发。真实业务、凭据和交付文件只留在本机私有状态目录，不属于公开源码。

## 已接入的生产端自动交接

调研与成本页新增工作项绑定，默认不绑定。明确选择产品与履约范围后，正常的检查、导出和测算就会保存同一份岗位产物，免去再次下载并导入组织 JSON。演示和修改过的演示测算仍不进入真实产物。工作项币种或范围改变后，旧绑定失效，须核对当前参数再更新绑定。

翻译原文在提交任务前留存，完成后以原始任务和原文哈希交接。模型译文一律待校对，人工译文不会被覆盖；原文已变化时拒绝应用旧结果。页面关闭或本地写入中断后，可在岗位页点击「同步已完成产物」恢复既有任务和回执，不重新提交模型。

图片对应关系由操作者明确绑定，默认只同步选中的已登记图片。同步复查源文件、交付文件、清单和创意版本；保存回执不等于素材可以直接上架。生产端交接使用来源版本前提，在同一事务中拒绝覆盖另一任务先保存的新版本。重复提交去重，A→B→A 的明确修改仍保留三个版本。

新增接口为独立的 `commerce_organization_exchange_*` 命名空间：`status` 只读，`produce` 运行明确指定的现有生产接口并保存产物，`bind_images` 保存图片映射，`sync` 仅接收已经存在的结果。未绑定的原领域 API 保持原有行为。不会启用飞书、增加定时任务或操作店铺。

`qa/test_organization_exchange.py`、`qa/organization_exchange_ui.mjs` 和隔离 Harness 验证交接去重、并行版本拦截、重开页面、译文待校对、图片完整性及跨客户端共享。合成验收使用固定翻译夹具，没有外部模型调用。
