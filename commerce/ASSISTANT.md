# 全程运营助手：对话、生成式界面与客户端接入

本轮已实现持久业务对话、上下文范围、追问表单、审阅建议和本地任务接续。浏览器与 Harness 使用相同的内联界面；Codex、Hermes、Harness 的工具调用使用同一个后台和数据库。

2026-11-16 通用助手接续：稳定知识、写作和翻译可直接回答；时效问题使用共享 `commerce_web_search` / `commerce_web_read`，不受当前业务页主题限制。公开检索复用项目已安装的 Open-WebSearch CLI，以有界请求运行；正文采用公开 HTTPS、固定解析地址和验证 TLS，不使用登录态或执行网页脚本。检索最多三个地区、每区限量，“今日”为北京时间日历日；搜索摘要、原文、发布日期待核对、日期范围外及部分失败分别展示。默认最多复用120秒缓存，明确刷新可绕过；原文不能读取时保留可用来源，不编造成功或把读取时间当发布时间。

明确要求保存公开分析时，复用原本地任务运行器，按原分析和来源哈希归档；“把上面的分析保存为简报”直接绑定原回答，不重新调用模型或网络。排队、完成、失败、取消和明确重试保持独立，助手可查看结果，任务账本可回到原模块和原会话。当前页面在每次发送时绑定，历史追问可以改变阅读位置；店铺、对象、版本与真实执行授权仍由服务端校验。以下早期按手动范围和右栏布局描述的记录仅代表其当时版本。

**当前交付状态是本机常驻服务已接入真实 Codex，公网部署与公开发布未执行。** 已使用本机现有 ChatGPT 登录的 Codex CLI 完成合成订单读取、三轮记忆、建议审阅及本地演示简报去重验收。常驻电商服务已在空闲检查与数据库备份后加载本轮代码；其它会话网关与手机服务没有重启。先前 Hermes 缺失的失败记录仍保留，未把合成模型回执冒充真实推理。

## 模型入口

2026-11-13 模型扩展首期：代码新增独立 `model_providers/`，私有页面 `/model-setup` 提供模型基础地址、模型ID、可选认证、合成推理测试和启停；支持 llama.cpp、vLLM 及自定义兼容聊天服务。对话中的选择保存在项目会话，每次请求保存模型/配置版本快照；活动请求不切换模型，失败与未知不自动换路重发。模型只提出结构化读取/回答，原运行器仍负责工具范围、数值与来源门禁。当前本机 llama.cpp 0.9.0 复用既有 Qwen2.5 3B 权重，完成合成对话和受限只读调用；这不是经营分析质量验收。vLLM目标服务与其它模型需各自实跑。

日常界面入口为智能对话的“对话模型 / 管理模型”及能力库的模型管理。配置返回后点击“刷新模型列表”读回目录和会话版本，未发送文字保留；当前模型停用或未就绪时阻止发送，不隐式回退默认模型。历史回答显示本轮实际模型，悬停可查看配置版本。日常后台已接入本机模型目录，正式React界面已用隔离状态验证，390px浅深色无横向溢出；新版Harness原生界面因Mac锁屏暂未验证。配置页接收凭据的接口仅限经过现有本机鉴权/来源校验的 `/v1/models/configure`；MCP只提供模型列表、选择和打开私有向导，不接收密钥。新配置默认未启用，保存不会推理；明确测试通过后再启用。模型选择不等于切换 Harness/Hermes/Codex 主执行宿主。

llama.cpp/vLLM应先以实际权重启动服务，再填写兼容API基础地址和服务提供的模型ID。模型管理不接受启动命令、不自动下载权重或安装执行代码。模型服务关闭后不会自动回退其它提供方。本机测试进程不等于已完成模型服务的登录后常驻和重启恢复；部署时另验服务生命周期。数据库备份仍是 `database_only`，模型密钥保存在私有 `model-credentials/`，须按私有资产单独备份，不进入公开包。

本机项目默认路线选用 Codex CLI 0.167.0-alpha.3.2、`gpt-6.1-sol`。登录由官方 CLI 自行读取和维护，不提取、复制或通过 MCP/聊天传递认证信息。项目默认路线保存在私有状态目录的 `agent-model.json`；会话模型选择单独保存在项目数据库，不改写该默认文件：

```json
{"provider":"codex","model":"gpt-6.1-sol"}
```

这个文件只接受 provider/model，不能注入命令、路径或任意参数；不存在时保留原 Hermes 路线。Codex 在空临时工作目录运行，忽略用户配置、项目规则与指令，关闭终端、插件、MCP配置继承、浏览器和其它应用能力，使用只读沙箱与结构化输出。允许的业务查询仍由父运行器检查并执行；发现额外工具事件会拒绝结果。取消或100秒超时会回收本次创建的进程组，不自动重试。以上开关只验收了当前 CLI 版本，其它版本需复验。

## 使用流程

1. 宽屏从右侧“运营助手”开始，收起后可重新展开；窄屏使用右侧入口打开抽屉。打开与查看记录不会调用模型。
2. 核对本轮模块、演示/本页来源、店铺、市场及明确对象，发送问题。
3. 助手使用现有有界执行器读取允许的资料，返回回答、依据、追问或待审阅建议。
4. 在生成式表单补充资料，明确点击发送。补充测算数据只更新会话范围，不自动调用模型。
5. 审阅建议的对象、操作和完整参数后，再明确提交一个本地任务；通过共享任务读取执行结果和产物复验状态。
6. 页面范围变化时，会话保持原范围，必须明确更新；旧范围的建议不能继续确认。刷新后可恢复已发送记录，较早记录可分页读取。

全量记录保存在本机数据库；单次模型输入最多参考最近6轮同范围对话，总历史输入限制32KB。未发送文字按页面、模式和会话范围保存；浏览器及Harness既有私有存储桥接可在重开后恢复，存储失败或版本冲突会保留当前输入并提示。轮询保留编辑器、选区、展开状态与阅读位置，组合输入结束后才刷新；范围切换时组合文字仍归原草稿。后台已有旧版本时显示未启用状态与刷新路径，不要求用户通过重复发送测试新能力。

## 2026-11-14 依据和功能补齐

助手内部可按冻结的任务/工作项身份检索项目记忆，仅接受查询文字，店铺、对象、模式和来源版本由后台决定。L1导入原文保持未核实，L2只读取有效的人工确认事实，L3只读取有效摘要；缺少明确范围时返回不可用，不退回全店查询。来源或事实变化会使旧依据失效；历史模型输入与建议提交也复验引用。此读取不新增公开MCP工具、事实写入或执行权限。

商品工作项的只读依据现在保留阶段名称、依赖、缺项原因、责任岗位和复验方法，供模型解释及依据卡直接查阅。HOLD是待补资料，FAIL是检查不符，BLOCKED是上游或能力受阻；数量仍为完整缺项数量，说明采用有截断标记的限量投影，不发送原始产物、表单或文件路径。依据卡标明历史快照；补齐资料后需重新读取原门禁，任务标完成不会代替产物复验。旧记录只有数量时提示重新读取，不伪造历史原因。

记忆依据、成本差异及原任务回执复用共享UI kit。排队、执行中、失败、取消与结果未知分别呈现，只有原任务结果和完成时间都存在才显示本地完成；确认应答丢失时查原任务，不重建或重发。商品缺项投影已加载日常Commerce；2026-11-14在Harness 0.2.2-rc.3实际发起一次只读模型请求，读取12阶段/20条缺项，原生展开原因、责任和复验、会话列表往返通过，未增加业务任务或执行动作。原生系统IME完整组合过程仍未验证。

供应报价和交付审阅沿用原工作项及产物账本。助手仅接收限量报价数值、版本和审阅缺项摘要，不发送供应方名称、原始备注或历史正文。报价版本/有效期或交付包/审阅回执变化时，运行中读取、历史模型输入及建议提交都会重新核对；陈旧回答不能继续作为创建任务的依据。技能页另有明确触发的只读执行条件检查，不创建任务、调用模型或扩大工具权限，详见[能力库](sealeap/README.md)。

本轮新增流程已通过真实HTTP、三路stdio MCP及1440/390px浅深色浏览器验收。日常Harness 0.2.2-rc.3另实际检查报价字段/单位、技能缺输入和输入变化撤下旧条件，无新增业务任务或模型请求。交付完整确认使用隔离状态下的已安装Harness Desktop Host及原生Chrome界面，保存待核清单、确认并回读原审阅回执通过；日常工作项没有内容草稿，未为验收向日常库填入合成内容。该隔离桥接验收不等于所有客户端原生版本均已通过。

## 业务闭环改进

- 简报保存并显示平台、店铺、市场、模式及来源摘要；筛选到单店后不再静默生成全局金额。历史未记录范围的简报保留明确状态。
- 从订单/示例商品创建的待办带服务端读取的对象、范围和来源指纹，不再只存标题。
- 通用待办可补齐本地操作并创建关联后续任务；保留原任务，创建不等于执行，不自动标完成。
- 知识等次要资料失败不会阻断经营数据；任务读取失败不显示成零待办。
- 19个业务模块直接放在单行顶部工具栏，来源状态、外观和设置共用该行；助手位于右侧。窄屏筛选和主要操作扩大热区。
- 调研与成本/补货输入支持按工作项显式保存与恢复；版本冲突保留当前输入，关闭或切换页面会使未完成的恢复请求失效。
- 研究导入、事实和来源引用采用共享结构化表单；高级JSON需明确选择。翻译、创意和选定技能共用私有Codex路线，仍保留各自来源与审阅校验。
- 可选视频 OCR 使用全部帧共享的20秒预算，单次最多8秒；超时保留关键帧并标部分完成，不把失败说成没有文字。

## 共享工具

| 工具 | 用途 |
| --- | --- |
| `commerce_copilot_open` | 幂等建立带明确上下文的会话，不启动模型 |
| `commerce_copilot_list` | 最近50个会话的元数据，不批量返回完整消息 |

## A2UI 与 A2A

实现范围、主来源、架构及限制见[协议说明](protocols/README.md)。原助手使用A2UI 0.8的小型标准组件集合，A2A使用0.3 JSON-RPC轮询子集；成本Surface另使用严格A2UI 1.0及统一成本契约，两者不视为同一协议或完整兼容。

生成式界面采用受控组件模式：模型给出结构化问题和建议，服务端映射为声明式组件，客户端只用共享组件渲染。模型不能提交HTML、脚本或任意新工具；公开网页只能经上述受限读取器获取。生成的审阅按钮只打开具体建议，真正提交仍经过后台范围/版本门禁。

HTTP的 `/.well-known/agent-card.json` 与 `/a2a` 复用现有本机鉴权、Host/Origin限制。支持message/send、tasks/get、tasks/cancel；无流式、推送、任意文件、远程回调或对外经营执行。同上下文的新问题用contextId及新messageId；不支持在同一个不可变taskId上续写。
