# 全程运营助手：对话、生成式界面与客户端接入

本轮已实现持久业务对话、上下文范围、同一输入框直接补充回答、审阅建议和本地任务接续。浏览器与 Harness 使用相同的内联界面；Codex、Hermes、Harness 的工具调用使用同一个后台和数据库。

当前为本机单用户工作台，已接入真实模型和共享任务账本；公开源码版本见[发布记录](../OPEN_SOURCE.md)。模型连通、界面、宿主实际执行与真实经营写入分别验收，不能互相替代。

## 模型入口

2026-11-13 模型扩展首期：代码新增独立 `model_providers/`，私有页面 `/model-setup` 提供模型基础地址、模型ID、可选认证、合成推理测试和启停；支持 llama.cpp、vLLM 及自定义兼容聊天服务。对话中的选择保存在项目会话，每次请求保存模型/配置版本快照；活动请求不切换模型，失败与未知不自动换路重发。模型只提出结构化读取/回答，原运行器仍负责工具范围、数值与来源门禁。当前本机 llama.cpp 0.9.0 复用既有 Qwen2.5 3B 权重，完成合成对话和受限只读调用；这不是经营分析质量验收。vLLM目标服务与其它模型需各自实跑。

日常界面入口为输入框底部的模型选择及“能力库 → 模型管理”。配置返回后点击“刷新模型列表”读回目录和会话版本，未发送文字保留；当前模型停用或未就绪时阻止发送，不隐式回退默认模型。历史回答显示本轮实际模型，悬停可查看配置版本；自动选择的实际执行端由本轮冻结回执核对。配置页接收凭据的接口仅限经过现有本机鉴权/来源校验的 `/v1/models/configure`；MCP只提供模型列表、选择和打开私有向导，不接收密钥。新配置默认未启用，保存不会推理；明确测试通过后再启用。固定模型选择与原生宿主自动选择分别执行，具体规则见下文。

llama.cpp/vLLM应先以实际权重启动服务，再填写兼容API基础地址和服务提供的模型ID。模型管理不接受启动命令、不自动下载权重或安装执行代码。模型服务关闭后不会自动回退其它提供方。本机测试进程不等于已完成模型服务的登录后常驻和重启恢复；部署时另验服务生命周期。数据库备份仍是 `database_only`，模型密钥保存在私有 `model-credentials/`，须按私有资产单独备份，不进入公开包。

本机“项目默认”固定路线选用 Codex CLI 0.167.0-alpha.3.2、`gpt-6.1-sol`。登录由官方 CLI 自行读取和维护，不提取、复制或通过 MCP/聊天传递认证信息。固定路线保存在私有状态目录的 `agent-model.json`；会话模型选择单独保存在项目数据库，不改写该默认文件：

```json
{"provider":"codex","model":"gpt-6.1-sol"}
```

这个文件只接受 provider/model，不能注入命令、路径或任意参数；不存在时保留原 Hermes 路线。Codex 在空临时工作目录运行，忽略用户配置、项目规则与指令，关闭终端、插件、MCP配置继承、浏览器和其它应用能力，使用只读沙箱与结构化输出。允许的业务查询仍由父运行器检查并执行；发现额外工具事件会拒绝结果。取消或100秒超时会回收本次创建的进程组，不自动重试。以上开关只验收了当前 CLI 版本，其它版本需复验。

## 自动选择与固定模型

开启私有状态目录的 `conversation-routing.json` 后，模型目录增加“智能选择 · 按任务选择”：

```json
{"mode":"auto","enabled":true,"priority":["dsh","hermes","codex"]}
```

智能选择按已登记能力、在线状态和优先级选择一个合格执行端，发送时冻结实际宿主、模型、路由版本和理由。文件缺失或明确停用时保留旧默认；配置非法或没有合格执行端时明确拒绝，不静默变为另一种模型模式。保持“项目默认”可选作为固定路线；手动选择本地/自定义模型后按该模型执行，不参与宿主自动替换。

模型目录通过 `default_model_id` 指明新会话默认项。欢迎页先读取目录再允许发送；打开会话时若默认项已经变化，会保留输入并要求再次明确发送，不在创建会话时偷偷执行。旧会话已有的明确选择保持不变；开启智能选择不改写其绑定或等待补充请求的已冻结路线。

等待补充时沿用原会话上下文和已冻结执行端；原执行端离线时不偷换另一端。原生研究等待补充时拒绝切换成与原计划冲突的模型。未知请求先核对原回执，关闭自动策略也不能绕过这项保护。研究任务可按原task_id显式恢复或取消，保留旧执行记录；普通对话进入unknown后停止当前会话，可明确新建会话，当前没有普通unknown会话的原地恢复接口。普通对话复用原Agent请求和租约记录，不为每句问候创建Core业务任务；市场研究继续以原task_id串起追问、采集、分析和候选保存。显式宿主分步计划与默认“选一个”是不同模式。

已确认的一般问候或纯算术可以直接回答，工具菜单为空且不得提出业务操作；业务状态、商品及经营判断仍需读取允许的证据，缺项不得编造。宿主登录由各自原生客户端维护，不提取账户令牌充当自定义API密钥。llama.cpp本地选项是否在线与回答质量分别核对；轻量模型不能据连通测试宣称经营质量通过。

从研究任务打开候选时，工作区携带该研究的上下文，读取对应的不可变产物，并可返回原任务。同一商品仍保持唯一身份；切换研究记录只切换只读报告，当前成本、内容输入和门禁保持当前版本。`commerce_workspace_get` 可选传入 `research_task_id`，服务器核对研究、候选和产物的绑定；不传时保持原有当前工作项行为。恢复后的对话使用同范围、同修订的当前研究状态与有效恢复结果，保留旧消息和执行回执。

## 使用流程

1. 从共享“智能助手”开始；宽屏与工作区并排，小屏在对话与工作区之间切换。打开、查看记录或刷新模型列表不会调用模型。
2. 核对本轮模块、演示/本页来源、店铺、市场及明确对象，发送问题。
3. 助手使用现有有界执行器读取允许的资料，返回回答、依据、追问或待审阅建议。
4. 直接在原输入框键入补充并明确发送；Enter换行，⌘ / Ctrl + Enter发送，输入法确认不提交。补充测算数据只更新会话范围，不自动调用模型。
5. 审阅建议的对象、操作和完整参数后，再明确提交一个本地任务；通过共享任务读取执行结果和产物复验状态。
6. 页面范围变化时，会话保持原范围，必须明确更新；旧范围的建议不能继续确认。刷新后可恢复已发送记录，较早记录可分页读取。

已发送记录保存在本机数据库；单次模型输入最多参考最近6轮同范围对话，总历史输入限制32KB。未发送草稿按会话或新会话范围缓存在当前浏览器；Harness 使用有来源和随机标识校验的本机父窗口存储桥接。草稿不进入模型或业务工具，刷新和重新打开后从相同缓存恢复；缓存不可用或版本冲突时保留当前输入并提示。清除浏览器资料、换设备或换 profile 后不保证恢复，这不是跨设备同步或长期项目记忆。后台已有旧版本时显示未启用状态与刷新路径，不要求用户通过重复发送测试新能力。

## 业务闭环改进

- 简报保存并显示平台、店铺、市场、模式及来源摘要；筛选到单店后不再静默生成全局金额。历史未记录范围的简报保留明确状态。
- 从订单/示例商品创建的待办带服务端读取的对象、范围和来源指纹，不再只存标题。
- 通用待办可补齐本地操作并创建关联后续任务；保留原任务，创建不等于执行，不自动标完成。
- 知识等次要资料失败不会阻断经营数据；任务读取失败不显示成零待办。
- 运营、商品、店铺、内容、情报、任务和能力库共用七个主工作区；智能对话与当前工作区并排，窄屏可切换。业务子视图继续复用共享模块和状态。
- 调研与成本/补货输入支持按工作项显式保存与恢复；版本冲突保留当前输入，关闭或切换页面会使未完成的恢复请求失效。
- 研究导入、事实和来源引用采用共享结构化表单；高级JSON需明确选择。翻译、创意和选定技能共用私有Codex路线，仍保留各自来源与审阅校验。
- 可选视频 OCR 使用全部帧共享的20秒预算，单次最多8秒；超时保留关键帧并标部分完成，不把失败说成没有文字。

## 共享工具

| 工具 | 用途 |
| --- | --- |
| `commerce_copilot_open` | 幂等建立带明确上下文的会话，不启动模型 |
| `commerce_copilot_list` | 最近50个会话的元数据，不批量返回完整消息 |
| `commerce_copilot_get` | 每页最多40轮；用before/next_cursor读取更早记录 |
| `commerce_copilot_send` | 按会话范围哈希发送一轮问题；复用已有模型队列 |
| `commerce_copilot_context` | 明确更新范围；版本变化使旧建议失效 |
| `commerce_copilot_cancel` | 取消本会话的一次模型请求 |
| `commerce_copilot_apply` | 按范围、版本和结果哈希审阅一条本地建议 |

`commerce_workflow_task_create` 与 `commerce_task_continue` 分别提供来源绑定的待办和关联后续任务。既有角色请求、任务、岗位交接与本地执行工具继续保留；不会复制宿主聊天历史。

## A2UI 与 A2A

实现范围、主来源、架构及限制见[协议说明](protocols/README.md)。本版固定 A2UI 0.8 的小型标准组件集合与 A2A 0.3 JSON-RPC轮询子集，不宣称最新版本或完整协议兼容。

生成式界面采用受控组件模式：模型给出结构化问题和建议，服务端映射为声明式组件，客户端只用共享组件渲染。模型不能提交HTML、脚本、URL抓取或任意新工具。生成的审阅按钮只打开具体建议，真正提交仍经过后台范围/版本门禁。

HTTP的 `/.well-known/agent-card.json` 与 `/a2a` 复用现有本机鉴权、Host/Origin限制。支持message/send、tasks/get、tasks/cancel；无流式、推送、任意文件、远程回调或对外经营执行。同上下文的新问题用contextId及新messageId；不支持在同一个不可变taskId上续写。
