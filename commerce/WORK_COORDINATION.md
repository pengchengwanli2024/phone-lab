# 并行协作约定

本文件是公开源码的通用协作指南。实际任务认领、聊天记录、设备状态、运行截图和经营回执保存在本机私有目录，不随源码发布。

## 修改与交接

- 开始前核对任务目标、文件归属及当前 SHA-256；记录不代替实际文件检查。
- 独立能力优先放入独立模块。修改共享服务入口、UI 构建或传输协议前，与当前负责人明确修改范围和顺序。
- 保留其它任务的未提交增量；不按旧副本整体覆盖共享文件，也不擅自重启其它客户端或服务。
- 交接记录实际改动、来源哈希、验证命令、退出码、未覆盖范围和可接续的原任务。准备完成、排队和自检通过分别记录。

## 构建与验证

- UI 的统一入口为 `python3 commerce/ui/build.py`；生成区块和源码保持同步，不直接编辑生成区块。
- 按 `docs/VERIFYING.md` 执行 `make verify` 及受影响专项。依赖缺失、检查失败、未运行或源码漂移均不能作为通过。
- 浏览器回归、宿主接口、原生客户端、真实设备和外部经营分别验收，不能互相替代。
- 测试使用隔离状态和合成资料，保留失败及结果未知的回执。不要通过跳过检查、假数据或重放未知请求制造成功。

## 业务与资料

- 商品身份同时绑定平台、店铺连接和平台商品；不能仅凭同名或同 SKU 合并不同店铺的记录。
- 原文、公开线索、生成建议、核实事实和负责人确认分别保存。生成素材、资料归档和选品候选不构成上架或采购批准。
- 来源或版本变化后重新检查原任务及评审；同一请求优先查询回执，结果未知时不盲目创建新请求。

## 私有状态与发布

- 凭据、个人路径、设备标识、真实店铺及客户数据、运行配置、数据库、日志和业务媒体留在私有目录。
- 发布使用独立脱敏候选，核对实际文件树、暂存内容、第三方许可和待推送历史；忽略规则不能代替内容检查。
- 发布专用文档处理与既有公开历史审阅分别留证，不修改本机原始协作日志来制造已清理的假象。
