# 有界 AI 运营角色

本模块接通私有选择的 Codex CLI 或原有 Hermes 模型路线，处理明确提交的本轮问题，执行受限读取并返回回答、追问及待审阅的本地建议。本机已使用现有 Codex 登录完成真实合成业务验收，模型选择与版本范围见[运营助手说明](ASSISTANT.md)。它不是无人值守的店铺经营执行器。角色来自现有 `agents/roles.json` 及其兼容别名，不另建或改写岗位体系。

## 使用与共享状态

进入「AI运营」，选择岗位和本轮读取范围，提交问题。模型会收到本轮问题、所选岗位和精简工具资料；不复制宿主聊天历史、不扫描整个知识库；共享工具资料不附带账户密钥或本机路径。用户本轮主动填写的问题及补充数据会用于本轮模型分析。当前模型路线沿用已有 commerce-bot profile，不在本模块中切换提供方或隐式降级到其它模型。

- 本机与连接状态：后台执行器、公共采集状态及连接快照的可用性、时间和记录数；不发送店铺名称、凭据、交易标识或买家资料。
- 公开情报：查询最新已采集元数据，每次最多向模型展示5条；单条读取限于本轮已返回或用户明确指定的 ID，不读取文章全文。来源资料未独立核实。
- 明确输入的测算：补充 `calculator` 和 `input`，如 `{"calculator":"unit_economics","input":{"currency":"USD"}}`。缺项保持 HOLD 并追问；模型不能改写明确输入的数值后再调用计算工具。
- 选定商品与岗位工作项：从当前连接已有工作项中明确选择商品和阶段；不自动导入、不替换为其它商品。模型只读取该工作项的岗位门禁与简报，工具资料保留市场、SKU、履约类型、币种与缺项，不发送其它工作项、供应商原文、图片路径或真实交易明细。
- 经营关联：在独立页面明确配置并计算后，模型仅能读取已展示的单份关联凭据。原始仓库坐标、路线点位和配置来源备注不进入模型投影。国家与距离匹配仅是复核线索，实际影响未知。具体规则见 [EXPOSURE.md](EXPOSURE.md)。

每轮最多3次模型分析、4次受限读取，最多8个排队请求，同一运行时一次处理1个请求。结果、工具回执、引用标识和输入/结果哈希保存在共享私有 SQLite 中。三个客户端读取同一请求 ID，不因面板刷新重新发起模型调用。

## 追问、建议与确认

缺少决定性资料时返回 `awaiting_input`。点击“补充回答”创建关联的新请求，保留旧问题与结果；继续使用同一岗位和范围，可更新明确提供的测算参数。

模型建议先保存为 `awaiting_review`，不会自己批准。界面展示完整本地操作及输入，确认后调用 `commerce_agent_apply`，传入请求 ID、建议 ID 和已展示的结果哈希。结果不匹配时拒绝执行。同一建议重复确认复用同一个共享本地任务。

本地建议支持模板简报、单件贡献、补货测算、冻结情报证据整理及下述岗位/经营关联复核待办。用户确认只覆盖该条本地建议，不构成采购、发货、改价、退款、广告发布或消息发送的授权。任务排队和已生成草稿不等于业务问题已经解决；继续在「设备与任务」查看本地执行回执。

`business_exposure` 仅接收 `parameters.assessment_id`。模型读取这份关联依据后可提出 `exposure_review`。确认时重新检查来源、配置和工作项身份，并复用已有共享复核待办；实际影响保持未知。依据变化会拒绝继续模型分析或首次派单。

工作项范围还支持 `organization_handoff`：先读取所选阶段的岗位简报，再由模型提出待补齐产物建议。确认时复用现有岗位派单方法和去重键，不另建连接、产物库或任务账本。该任务保持 `execution=not_requested`，等待岗位补齐真实产物，不交给模板执行器冒充完成。

商品、币种、阶段或依据变化后，旧建议确认会被拒绝。依据复核、原有派单和确认关联记录在共享任务核心的同一事务中完成；即使两次领域检查之间出现变化，本次派单也会回滚。重复确认已提交的建议返回原任务，不因后来数据变化重新派单。

点击“复验当前门禁”会重新读取现有岗位检查。任务被标为完成不能使门禁通过；实际补齐并验证产物后，门禁才可能 PASS。门禁通过仍不代表经营操作完成、独立事实核实或商业闭环成功。

## 取消和恢复

排队请求可以取消；运行中的请求发出停止信号并终止本次拥有的模型子进程，不终止其它会话的进程或网关。已经发出的生成可能仍产生用量，取消不承诺提供方侧没有计费。

模型调用超时或结果未知时不自动重发。重复幂等键继续返回原请求；用户检查后可明确提交新的请求。进程中断会保留 `interrupted`，不会在重启时重放原模型请求。服务正常退出会停止本模块拥有的子进程；意外强制杀死进程时仍不能承诺提供方侧生成已停止。

工具菜单只包含该轮范围允许的读取/计算方法。模型提出其它工具、改变计算输入、引用不存在的依据或超过预算时，请求明确失败，不静默扩大权限。

## 接口

| 方法 | 用途 |
| --- | --- |
| `commerce_agent_status` | 运行器、岗位、范围和限额；提供方可用性在请求时核对 |
| `commerce_agent_cases` | 列出当前连接已有工作项，最多返回200项；不自动导入 |
| `commerce_agent_case_check` | 读取某条岗位建议当前的任务、缺项和门禁状态；不修改产物或关闭门禁 |
| `commerce_agent_start` | 明确提交 question、role、topic、idempotency_key；可带 parameters / parent_id |
| `commerce_agent_list` / `get` | 最近共享记录或完整结果及工具回执 |
| `commerce_agent_cancel` | 取消排队或请求停止；不撤销已经确认的本地任务 |
| `commerce_agent_apply` | 对已展示的单条建议按结果哈希提交本地执行 |

调用模型只发生在明确请求之后，不因浏览器加载、定时采集或连接检查自动触发。所有模型输出仍待核对；引用和哈希不证明业务事实真实。

## 开发与并行边界

源码独立放在 `agent_runtime/`；界面规范源为 `web/agent-ui.js` / `agent-ui.css`，统一构建内联到既有 app.js/style.css。新模块复用 Commerce UI 的按钮、表单、弹窗、状态和设计变量，遵守现有三资源 iframe 协议。

开发登记见 [WORK_COORDINATION.md](WORK_COORDINATION.md)。岗位门禁、技能目录、桌面采集任务、Ozon 适配和创意模块由其它会话维护，本模块不重写这些实现。验收截图、模型合成结果及本机活动记录保留在私有运行目录，不随公开源码发布。
