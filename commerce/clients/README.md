# 同一业务后台的客户端接入

这些配置是本机单用户MCP stdio入口。各宿主使用同一项目路径、COMMERCE_STATE与COMMERCE_PORT，不各建一份数据库。client参数用于记录调用来源，不是权限或身份验证。

2026-11-13 已确认部署目标：三端可接入，默认智能三选一承担一项任务，支持指定主执行端；其它客户端可查看，同任务不重复执行。项目独立保存业务数据库、记忆、技能/插件版本及任务回执，换宿主不新建业务副本；不要求关闭其它项目的应用或网关。当前连接配置不包含完整自动选择/执行互斥机制，该目标按[需求台账 A08](../../docs/PLATFORM_BACKLOG.md)单独实施验收。

## Codex

使用[配置模板](codex.toml.example)，将项目位置占位符改为本机实际源码位置，并在原有MCP配置中增量加入commerce；保留其它MCP、模型及账号设置。新工具缓存按当前客户端机制刷新，不覆盖整个配置文件。

## Hermes Agent

使用[配置模板](hermes.yaml.example)，合并到独立项目profile的mcp_servers。保留原有模型、渠道和其它项目网关；配置MCP不等于启动手机机器人。项目内助手的模型由服务端私有配置选择，可用Codex CLI或既有Hermes入口，与调用MCP的宿主分开。本机已直接复用Codex登录完成真实推理；未配置私有选择时保留原Hermes路线，依赖不可用会返回接入错误，不自动重试。配置与实际验收版本见[助手说明](../ASSISTANT.md)。

## DeepSeek Harness

复用现有 `commerce/harness/` 插件，其owner-only Connection Fetch与受限iframe读取相同内联产物。安装或更新前核对当前宿主版本与任务归属。原生面板需要后台加载新增工具，但不能通过重启其它会话的服务或网关来代替核对。

## 验证边界

历史stdio MCP验收覆盖三个client名称读取同一个会话、发送、追问与恢复；这不等于这些宿主所有版本的原生界面兼容。2026-11-13本机复验：Harness 0.2.2-rc.2日常原生工作台可加载，真实 DeepSeek 模型调用 commerce_status 并返回0.1.0；Hermes Agent v0.23.1+2的默认及项目profile通过已安装原生MCP客户端读取同一商品和成本Surface，发现186个工具；当前Codex会话实际MCP读取同一对象，两端合成贡献38 CNY及缺项HOLD均通过。Hermes项目既有provider和项目Codex CLI另以无工具合成请求验证模型可用。工具数是该次发现快照，不作为固定兼容契约。

以上为本机安装、模型及工具接线验收；不证明默认三选一调度、三端原生富组件、真实店铺写入、手机/App指定操作、消息收发或服务器部署完成。Hermes/Codex当前返回文本、结构化数据及受保护工作台链接，不承诺原生聊天自动渲染A2UI。完整证据与备份保留私有运行目录。

本地服务继续仅监听回环地址。跨机器、TLS、用户身份或多租户部署是独立接入任务，不直接把本机鉴权令牌暴露公网。
