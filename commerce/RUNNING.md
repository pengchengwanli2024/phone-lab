# 独立运行与本地执行

共享后台可以独立于 Harness、Codex 和 Hermes 窗口运行。浏览器使用同一套界面和数据库；三个宿主使用同一套接口。当前是单机、单用户本机版，不是已完成授权的多平台自动经营服务。

## 启动

在项目根目录使用 Python 3.11 或更新版本。后台核心只依赖 Python 标准库；A2UI 1.0 成本界面的严格校验另需 `a2ui/requirements.txt` 中的可选依赖。建议安装在项目私有虚拟环境，并用同一解释器启动后台和安装本项目常驻服务，不全局升级 Python 包。浏览器运行不需要 Node 网关、模型账户或运行时 CDN。Harness 插件另需兼容的宿主和 Node；手机控制与创意媒体工具各有独立前置条件。

```bash
python3 commerce/manage.py start
python3 commerce/manage.py open
python3 commerce/manage.py doctor
```

`start` 幂等启动同一个后台，关闭终端或聊天窗口不关闭后台。`open` 生成短时一次性本机访问票据并打开浏览器，不在终端打印票据或服务凭据。`doctor` 返回服务、执行器、采集计划及授权准备状态；`ready_local` 仅说明本地运行链路可用。

`doctor` 还按四个平台输出已保存、启用、缺快照、陈旧、读取异常和活动读取的计数，不输出店铺名称、标识、凭据或业务记录。未授权不影响本地链路就绪，仍然不代表经营验收通过。若运行进程尚未加载当前的结果限制，返回 `degraded` 和 `read_connectors.status=update_pending`；元数据不可核对时保留 `unknown`。诊断不保存配置、重发作业或重启服务。并行开发期间必须先核对当前任务归属及所有活动作业，再安排加载新版本。

默认监听 `127.0.0.1:38731`。私有运行目录默认是项目的 `.commerce-state/`。可以显式设置 `COMMERCE_STATE` 和 `COMMERCE_PORT`；同一组客户端必须使用相同值。不要把私有运行目录提交、公开或复制进前端包。

持续部署可以前台运行，由所选进程管理器监督：

```bash
python3 commerce/manage.py serve
```

Mac 当前用户登录后自动启动及退出恢复：

```bash
python3 commerce/install_runtime.py
```

安装器只管理本项目 LaunchAgent。重复运行会核对并保留已有正确配置；冲突配置报错，不替换无关服务。客户端发现匹配且已加载的本项目 LaunchAgent 时等待其健康，不另起竞争进程；隔离状态目录仍可独立启动。Mac 休眠、断电或用户退出时不承诺在线。Windows 的进程锁和常驻方式尚未适配。

## 计划采集

在“设备与任务 → 独立运行中心 → 采集设置”启停八个已注册公开源：USGS、GDACS、WTO、美联储、ECB、EIA、HMRC 与英国交通部门；选择 5、15、30 或60分钟。新安装默认暂停；启用后计划保存在 SQLite，后台自动运行且跨重启保留。现有本机部署是否启用以运行中心为准。

采集不依赖浏览器刷新。定时与手动采集进入同一持久队列，按来源排他领取；失败不会覆盖旧快照，也不会立即连续重试。来源采集仍受来源/主机间隔、大小、配额与网络等待限制。最近全部来源成功时间与各源结果分别展示，不能把调度器在线当成源数据最新或真实。

关注主题仍是共享检索条件。开启公开源计划不启用飞书、消息通知、模型调用、店铺同步或任何平台写操作。

## 本地执行与追问

任务创建与执行请求分开。自由描述只排队；后台不会把任务正文、笔记或网页内容当作脚本和工具指令。

| 本地操作 | 结构化任务要求 | 结果 |
| --- | --- | --- |
| `report` | `kind=report`，可选布尔值 `input.demo`，默认真实模式 | 本地模板简报草稿；真实模式引用可用快照的记录数、时间与范围，金额仍未知；幂等归档到账本 |
| `intel_review` | `kind=analysis`，`input.mode=public_source` 与完整冻结的 `input.evidence` | 来源证据、未知业务影响及待追问事项；不是独立事实核查 |
| `unit_economics` | `kind=analysis`，`input.parameters` | 既有单件贡献计算；缺项返回 HOLD |
| `restock_plan` | 同上 | 既有补货计算；不创建采购或调整库存 |

接口顺序：

1. `commerce_task_create` 创建带幂等键的任务，或 `commerce_intel_review_create` 绑定已展示的情报内容版本。
2. `commerce_task_execute({task_id, operation})` 明确请求其中一种本地操作。
3. `commerce_task_result({task_id})` 获取持久回执。相同执行请求不会重复处理；操作冲突被拒绝。
4. 本地失败或重启中断会保留 `failed/interrupted`，必须显式调用 `commerce_task_retry` 才会重试。未开始的任务可以取消，已完成结果不能改写为已取消。

执行器最多每轮处理8个明确请求的本地任务。结果不调用 LLM，不执行 shell、设备操作、买家消息、退款、发货或改价。岗位契约配置与真正的模型执行器是两个状态；移动网关仍按原计划另行授权、接入和验收。

## 数据备份

```bash
python3 commerce/manage.py backup
```

使用 SQLite 在线备份并检查完整性，保存在私有运行目录的 `backups/` 下，文件权限为0600。包含业务账本与本地资料，不包含凭据、连接配置、知识库或媒体文件，不能把它当作整套部署备份。终端只输出备份文件名和检查结果。

恢复须先停止拥有该运行目录的服务，保留当前数据库备份，再离线核对备份完整性并更换数据库；配置、凭据、知识库与媒体需分别恢复。当前没有自动覆盖在线账本的恢复命令。

## 连接异常与验收边界

知识笔记单次正文读取有3秒超时；操作系统或移动磁盘访问未完成时返回明确错误，不一直占用请求，也不修改原目录和权限。超时并不证明是系统权限问题。

本地就绪不等于真实店铺已授权、飞书机器人已上线、模型可自主经营或生产全天候部署已通过。WorldMonitor 正式数据、真实经营口径与写操作、移动机器人及常驻服务器迁移仍分别需要配置和验收。其它四平台已有独立的有界只读实现及私有接入向导，尚需真实授权、适用范围、签名和口径验收，见 [多平台连接](PLATFORMS.md)。已有家居候选可通过 [商品试点](PILOTS.md) 接续来源与原任务，不虚构店铺 SKU 或库存。

可重复的合成检查包括 `qa/test_autonomy.py` 和 `qa/test_standalone.py`；后者实际创建隔离服务、杀死进程、重启、读取原结果、恢复中断状态，并通过三个 stdio 客户端读取同一回执。测试不连接真实店铺或发送通知。
