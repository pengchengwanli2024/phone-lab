## 1. 项目定位与当前阶段

按[常驻团队要求](../commerce/AGENT_TEAM.md)，项目目标是由 AI 驱动的跨境电商管理系统，先在 Mac 联调，后续迁移常开服务器。手机控制是底层能力之一；当前主要产品已扩展为共享电商工作台。

建议采用以下统一描述：

> 面向本机经营者的跨境电商工作台，以共享后台连接浏览器、Harness、Codex 与 Hermes，完成有来源的研究、测算、内容草稿、任务交接和产物复验，逐步接入真实店铺、移动通知与经明确授权的经营操作。

当前阶段是**本地工作台与受限 AI 协作已实现，真实经营闭环尚未完成**。不能把模拟数据、连接器代码、本地任务成功或岗位门禁通过合并表述为“无人值守经营已上线”。

| 层次 | 组成 | 对齐后的责任 |
| --- | --- | --- |
| 产品入口 | 浏览器、Harness 内嵌工作台、Deepseek harness/Codex/Hermes MCP | 使用同一业务后台、对象、版本与任务；宿主聊天外观由各客户端管理 |
| 协作与控制 | 运营助手、有界模型运行器、岗位契约、共享任务 | 提问、受限读取、补资料、审阅建议、执行本地操作、复验产物 |
| 业务模块 | 店铺读取、研究选品、测算、创意、客服草稿、情报 | 各自提供明确范围的能力，不因共用界面而自动获得其它模块权限 |
| 支撑能力 | 桌面采集、手机 ADB/WDA、知识目录、备份与运行管理 | 按环境与设备分别接入；设备控制尚未进入电商自动任务队列 |

| 客户消息 → 回复 → 审阅 → 发送 → 收件核对 | 本地会话资料、回复草稿、引用和审阅 | 官方渠道身份与授权、接收事件、真实会话映射、发送及收件回执 |
| 本机运行 → 常驻服务器 → 移动入口 → 故障恢复 | 本机服务监督、共享接口、数据库副本恢复 | 目标服务器/访问边界、目标机模型与依赖、渠道收发、完整资产恢复及故障通知 |

**“本地流程验收”与“真实经营完成”应保留为两个里程碑。** 上架、改价、发货、退款、采购、广告和客户消息已有部分草稿准备能力，尚无已验收的通用外部执行闭环。

## 5. 状态与验收口径

各领域保留自己的状态机；统一展示含义，不强行把所有状态改成一套枚举。

| 状态轴 | 应分别回答的问题 | 不能混同的状态 |
| --- | --- | --- |
| 数据与依据 | 数据从哪里来、何时读取、对象和版本是什么、是否已核实 | 有快照 ≠ 当前新鲜；已查看/收藏 ≠ 核实；未知 ≠ 0 |
| 连接与授权 | 配置是否存在、权限是否有效、范围是否确认、通知是否实收 | 已配置 ≠ 已授权；接口接受 ≠ 手机收到；本机健康 ≠ 业务健康 |
| 任务与执行 | 是否明确请求执行、由谁执行、结果是否已知、能否重试 | queued ≠ running；本地 succeeded ≠ 平台操作完成；unknown 不自动重发 |
| 产物与业务门禁 | 是否为草稿、是否审阅、引用是否仍有效、实际产物是否复验 | 已审阅 ≠ 对外操作授权；任务完成 ≠ 门禁 PASS；PASS ≠ 商业收益 |

建议每项验收至少记录：需求编号、对象/店铺/市场/履约范围、数据模式、来源版本及时间、输入与币种、执行器、审阅范围、结果回执、复验方法、环境/宿主版本和未覆盖项。敏感内容保存在私有状态目录。

模型样本、合成测试、浏览器测试、Harness 原生桥接、实际 MCP 调用、真实店铺及真实设备分别计证；不能相互替代。不同日期的测试数量有重叠，不相加为总覆盖率。
