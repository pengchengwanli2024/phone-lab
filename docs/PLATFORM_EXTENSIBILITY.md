# 智能跨境运营平台 · 技能、插件与扩展规范

状态：目标规范，尚未实现为统一扩展系统。与[产品主稿](PLATFORM_REQUIREMENTS.md)、[交互设计](PLATFORM_EXPERIENCE.md)、[需求台账](PLATFORM_BACKLOG.md)共同使用。已有共享服务、技能目录和平台适配继续复用。

2026-11-13 用户确认：项目独立拥有数据库、记忆、技能与插件系统；Harness、Hermes、Codex 是可替换宿主，默认智能三选一运行。以下合同为实施与验收目标，不把宿主已经安装的能力自动登记为项目已启用。

## 项目资产与宿主选择（A07–A08、X01–X03、O01）

项目核心持久保存业务账本、项目记忆、技能/插件登记和执行回执，宿主通过统一接口读取最小任务上下文。项目记忆记录来源、对象/项目作用域、版本、观察时间、事实/推断、有效性和审阅状态；撤回或过期后不再作为当前依据，历史引用仍可解释。技能保存方法与输入/产物合同及版本，插件保存能力、依赖、适配版本、私有配置引用、启停及验收状态。三者不能仅存于宿主聊天或全局安装目录。

默认主执行端只能是 Harness、Hermes、Codex 之一。调度前按有效授权、真实能力与版本、健康、资源占用、任务适配及可知用量筛选，记录候选缺口和选择理由；用户指定时仍检查这些前提。运行平台与模型提供方分开登记，不能因选择 Hermes 就假定必须更换项目模型。其它客户端可查看同一业务，安装/打开状态不构成执行权。

同一任务的活动执行权由项目核心互斥保存，包含主执行端、尝试、租约/心跳及接管记录。宿主失联后先停止后续派发并核对原尝试、外部回执和设备占用；租约过期不证明外部动作未发生。仅在结果已核清且允许继续时接管原任务，禁止对 unknown 自动换端重发。独立任务与明确授权的专项并行遵守已有资源互斥，不把三选一扩成默认三端竞跑。

部署验收分别覆盖三端可接入、单端选择、并发抢占、失联/未知接管及项目资产备份恢复。当前共享接口、业务存储和静态目录可复用；统一调度、记忆管理及完整扩展生命周期仍待实现，不能由 MCP tools/list 通过代替。

## 1. 能力分层（X01）

| 类型 | 它提供什么 | 不应混同 |
| --- | --- | --- |
| 技能 / 方法 | 任务适用条件、输入、步骤、交付与复验要求 | 文档读取不代表工具、账号或执行器可用 |
| 工具 | 一次明确的类型化读取、计算或动作 | MCP 描述和注解不构成授权 |
| 执行器 | 持有本次范围、预算和取消权的实际运行单元 | 接受任务不等于完成业务；不允许来源内容直接执行命令 |
| 连接器 | 平台授权、资源读取/写入、字段与分页/水位转换 | 某一平台资源可用不等于该平台所有业务可用 |
| 模型提供方 | 明确的模型路线、支持的输出/媒体形式及用量回执 | 当前研发助手能调用不等于平台后台能调用 |
| 界面扩展 | 已登记的业务组件及声明式数据与动作 | 组件包不是独立业务数据库，不提供任意脚本注入 |
| 渠道 / 外部智能体 | 消息接收、通知、确认或有范围的任务委派 | 渠道身份、用户权限、任务归属和收件要分别校验 |

一个插件可打包以上多类能力，但每一项单独声明、测试和启用。当前助手会话可使用的第三方设计、图像或视频插件，不自动成为 phone-lab 运行时插件；如需接入，必须有独立适配、授权、数据范围及可恢复回执。

## 2. 统一能力登记（X01、X03）

首先登记现有内置能力，随后接外部适配。以下字段是平台内部目标合同，不宣称属于现行 MCP/A2UI/A2A 标准字段。

| 字段组 | 最少内容 |
| --- | --- |
| 身份与来源 | `capability_id`、类型、名称、版本、维护者、来源/包哈希、许可和变更摘要 |
| 业务适用性 | 平台/市场/经营模式、任务类型、前置输入、限制、输出产物类型 |
| 调用合同 | 输入/输出 schema、执行器引用、只读/本地写/外部写分类、幂等语义及批量边界 |
| 权限和数据 | 所需授权作用域、可读取字段、出站目的、敏感字段投影、数据留存及对象范围 |
| 资源控制 | 最大耗时、模型/请求/并发/文件额度、已知计费方式、超额行为、取消检查点 |
| 生命周期 | 安装/配置/启用版本，凭据有效性、能力探测、兼容宿主、健康与降级结果 |
| 结果核验 | 来源及测试版本、离线/合成/真实回执、检查器、外部回读方法、未知处理和补救方式 |
| 界面贡献 | 受支持组件目录、配置字段、可读状态、已有页面入口；不注册任意脚本和私有业务状态 |

“撤销”必须说明撤销的是权限、后续调度、已生成产物还是外部动作；无法撤销的平台动作不能展示通用“撤销”按钮。回退插件版本也不能承诺撤回已经发生的经营行为。

## 3. 能力可用性与任务匹配（X01、X02）

保留多条状态轴：来源完整性、执行器可用、账户/数据就绪、验证范围、当前健康。不能用一个绿色“已安装”覆盖它们。

面向用户的能力页首先回答：**适合本次任务吗、现在能运行吗、还缺什么、会生成什么、需要哪些权限、有哪些已知限制**。其次再展示技能正文、工具 schema 和技术来源。

匹配顺序为：业务目标→平台/对象→输入是否齐全→账户与资源范围→执行器是否可用→版本与验证→用量和策略。模型只能从通过这些约束的候选中选择；不把全部工具或797项原文同时放入上下文，也不凭标题相似替代适用性检查。

现有 SeaLeap 保留 797 项顶层、19 个专用离线入口、778 个草稿准备入口与227个细分模式。推荐优先补齐高频路径的领域检查器和真实输入样例；不以增加目录数量作为平台扩展成功指标。需要新技能时，先比较已有输入/产物契约，避免复制相同方法和任务。

目标能力还包括技能与工作流的创建/改编：从缺口建立草案，填写适用范围、输入、步骤、工具依赖、产物和检查器，提供合成样例，隔离试运行后审阅发布新版本。AI 可协助写草案和生成测试资料，不能自行安装执行代码、扩大权限或替换正在运行的版本。可复用流程保存为计划模板，实例化时重新绑定真实对象与有效能力；导入/导出仅携带合同和公开/合成样例，不携带凭据、真实资料或运行账本。

| 能力层次 | 界面能做的承诺 |
| --- | --- |
| 仅有方法 | 可读原文和准备资料，执行方式未接入 |
| 草稿执行器可用 | 可生成受限文字草稿，真实业务输入/输出仍需检查 |
| 离线脚本已验证 | 指定脚本、版本及输入样例通过，不代表完整技能或账户操作 |
| 真实资源已验证 | 指定账户、区域、资源、权限和时间下有真实回执，不外推其它资源 |
| 范围内启用 | 在已生效策略内可运行；仍需本次输入、来源、健康和额度检查 |

质量检查至少分 schema/引用检查、领域规则、人工适用性及真实结果。测试失败、HOLD、needs_inputs、unknown 均保留；模型自评不能替代独立检查器。

## 4. 接入、升级和停用（X03）

推荐生命周期：**发现 → 来源/许可核对 → 安装或登记 → 私有配置 → 能力探测 → 隔离合同测试 → 真实只读验证 → 启用指定范围 → 观察与升级/停用**。不要求每类能力都访问外部账户；纯离线计算按其类型完成适用步骤。

内部轮询、手动请求、定时器及后续 webhook 都转换为有稳定ID、发生/接收时间、来源、对象范围和版本的事件；外部事件另验签名、重放和身份。流程模板只订阅明确登记事件，不因安装扩展自动增加后台调度。

| 操作 | 用户看到什么 | 系统必须做什么 |
| --- | --- | --- |
| 添加扩展 | 功能、数据访问、运行方式、费用依据、前置条件及维护状态 | 不凭自然语言说明安装任意依赖或执行第三方脚本 |
| 保存配置 | 已保存与尚未验证分开 | 凭据只写受保护配置，不经模型、聊天、MCP参数或组件状态回显 |
| 探测/测试 | 明确只测哪些资源、合成还是真实 | 先执行无副作用探测；测试写入另需范围与测试对象 |
| 启用 | 店铺/对象/角色/计划、允许动作、频率和限额 | 默认关闭自动任务，启用不扩大为全局授权 |
| 升级 | 版本差异、合同/权限/数据迁移影响和测试结果 | 固定新版本验证；权限或输出含义变化重新审阅；旧任务保留旧版本 |
| 停用 | 新任务停止，活动任务处置及历史可读性 | 停止后续派发；只取消拥有且可取消的任务；结果未知进入核对 |
| 移除 | 配置、凭据、产物、业务引用的处置范围 | 不级联删除有引用的历史；数据清理由保留规则单独决定 |

暂不建设开放市场。首批扩展以现有内置模块的登记与合同自检为主，再按真实工作缺口接店铺资源、媒体工具、客服渠道、物流、广告或结算数据。商品数据、规则和素材授权随具体使用核对。

## 5. 智能体、技能与插件如何协作（A03–A06、X05）

1. 编排器根据目标建立计划版本，匹配既有岗位和产物契约。
2. 准备步骤按最小上下文读取证据，并检查输入、连接、额度和能力版本。
3. 角色可提出工具/技能组合；执行器再次核对业务身份、动作策略和来源前提。
4. 方法生成结构化结果，确定性工具进行数值和领域检查，产物存入原模块并返回稳定引用。
5. 计划按检查结果继续、请求补充、转人工或等待审阅；失败不得通过更换插件绕过限制。
6. 本地完成与外部提交分别留回执；平台终态需回读。外部结果未知时先核对原记录，不自动切换执行器重发。

并行只用于输入独立且不会争用同一对象的步骤；店铺资源、媒体槽、设备及文件分别互斥/限流。订单、财务数值和同一商品产物的版本提交由共享核心检查，不能以模型间“达成一致”替代事务或事实核对。

有模型自动计划时，记录计划的最大模型轮次、可调用能力、单轮及周期预算、停止条件和责任人。未返回可靠用量/费用的提供方显示未知或已核对的上限，不能填0或伪造费用。

## 6. 平台、媒体、设备和渠道适配（X04）

| 适配类 | 必须声明与验证 |
| --- | --- |
| 电商平台 | 账户/市场/经营与履约模式、资源、原始标识、字段口径、分页/同步水位、时区、限流、过期与部分失败 |
| 广告/结算/物流 | 期间、币种、归因或费用口径、延迟/修订、与商品/订单的映射，不能从缺数据推断0 |
| 图像/视频/配音 | 输入类型、出站素材/事实范围、版本、费用、处理状态、可取消性、产物文件及权利复核 |
| 客服/通知 | 渠道与用户身份、事件去重、权限、对话映射、发送/接口接收/实际收件、人员接管 |
| 手机设备 | 设备明确归属、授权任务、互斥/租约、生命周期提示、干净原图、实际应用专项验收 |
| 手机浏览器 / App 采集 | 明确设备、App/浏览器版本、账号及页面/商品/评论范围；保留原文、时间、链接或页面定位、采集方式与证据哈希；标明可见样本、翻页终点和缺失，截图/OCR不冒充结构化全量接口 |
| 电脑浏览器 / 工具采集 | 明确会话/账号和网址、工具版本、公开/登录资源范围、分页/游标、限流及采集时间；来源内容不作指令；DOM、导出、API或采集器产物按同一来源合同入库 |
| 浏览器 / App 指定操作 | 区分浏览、搜索、读取评论与发表/回复、提交表单、修改业务等动作；绑定账号、目标、参数和授权；每次尝试记录回执并读回结果；unknown先核对，不能跨设备或换宿主重发 |
| 知识与文件 | 选定目录/资源范围、文档版本、引用、大小及访问校验，不扫描无关知识或注入永久记忆 |

设备是被明确选择的执行资源，不是所有 API 失败后的自动替代路径；平台和应用限制不会因接入手机而消失。iPhone XCTest 提示限制继续保留，电脑提示不混入采集原图。

四类通道共用项目采集/任务/证据存储；同一资料通过稳定来源标识及内容版本关联去重，保留各通道观察时间、样本及差异。读取、采集和指定操作各自验收；验证码、登录失效、设备忙或来源限制返回缺项/等待，不能生成成功回执。具体目标网站、App和动作清单按实际任务确定，不宣称任意网站或任意操作均支持。

## 7. 协议、宿主与生成式界面（X06）

协议实现与业务合同分开版本化。现有项目固定 MCP 适配器、A2UI 0.8 五组件快照子集及 A2A 0.3 轮询子集；不因外部规范演进就宣布当前兼容新版。

| 通道 | 目标职责 | 验收要求 |
| --- | --- | --- |
| 共享 HTTP / MCP | 领域工具发现和调用，传递稳定对象、版本与回执 | typed schema、权限、作用域、幂等、错误和真实工具调用；工具可见性与调用授权分别校验 |
| A2UI 或内部视图合同 | 用已协商组件呈现资料、计划、比较、审阅和结果 | 组件目录/大小/动作版本校验；不支持时降级；浏览器与 Harness 使用同一业务合同 |
| A2A | 有限的外部智能体发现、任务委派、查询和取消 | 可信身份、任务归属、能力和授权范围；明确支持的轮询/流式/推送，不把终态旧任务重新写入 |
| 渠道卡片 | 手机上查询、补充、决策和定位原工作 | 同一对象与确认绑定，消息去重；不假定渠道能渲染浏览器组件或改变原生聊天外观 |

本轮参考官方资料核对的是设计原则：MCP 区分 tools/resources/prompts；A2UI 的组件目录约定模型和渲染器可表达的组件；A2A 将上下文、任务和产物分别组织。这些原则支持本项目的分层设计，不表示已经安装新 SDK 或实现全部规范。[MCP 服务端概念](https://modelcontextprotocol.io/docs/2026-07-28/learn/server-concepts)、[A2UI 组件目录](https://a2ui.org/concepts/catalogs/)、[A2A 任务生命周期](https://a2a-protocol.org/latest/topics/life-of-a-task/)（查阅于2026-11-12）。

A2UI 官方页面本轮标示 v1.0；当前项目仍为0.8子集。是否迁移应依据目标宿主、所需组件、转换成本及合同回归决定，先评估再独立实施；不将追逐版本号列为业务完成条件。旧客户端保持明确兼容路径，不静默改变既有结果结构。

## 8. 扩展验收清单

### 模型、媒体与配置工作流的独立适配（2026-11-13，X07–X08、O06）

用户确认继续通过模块和插件扩展，首期优先模型选择、自定义和本地模型。宿主选择、模型推理、媒体制作、业务工作流和移动控制分层，均复用项目存储与任务/产物引用：

| 扩展 | 接入职责 | 独立验收 |
| --- | --- | --- |
| llama.cpp / vLLM | 已部署模型服务的兼容聊天API适配，提供模型ID、认证和输出能力 | 指定服务版本/硬件/模型实际推理、结构化结果、取消、资源与未知处理；测试通过不证明所有模型或原生工具调用可用 |
| 自定义模型服务 | 由用户保存可信基础地址和模型ID，按明确API合同增加适配 | 私有凭据、地址校验、能力差异、连接测试、启停及错误；API名相同不假定全部参数兼容 |
| ComfyUI | 图像/视频等媒体工作流执行器，固定工作流、节点、模型及输入版本 | 保存原prompt_id，分别处理排队/运行/失败/未知/产物；核输出文件、来源与工作项交接，不把入队当成片成功 |
| 类Langflow工作流配置 | 类型化节点的可视化图、校验/试运行/发布；可选外部引擎适配 | 原任务账本、节点/流程固定版本、条件/依赖/补充/审阅、取消与恢复；外部流程导入先映射已登记能力，不直接执行代码节点或安装任意节点包 |
| 独立移动管理端 | 远程连接项目控制面，对话/模型、任务、审阅、产物、扩展及已授权设备控制 | 可信设备配对、服务端身份/作用域、撤权、审计、失联/重复请求与控制互斥；目标客户端与真机专项验收 |

对话模型选择持久保存到项目会话，业务上下文与模型选择各自校验；每次请求固定配置快照，切换只影响后续请求。新模型保存后明确测试与启用，不自动发送业务资料。密钥仅由私有HTTP向导接收，SQLite和MCP只保留不可逆回显的状态/私有引用；不进入模型提示词、聊天、项目记忆和前端持久缓存。旧凭据引用可能被活动请求使用，清理与撤权要区分，数据库备份不等于凭据备份。

模型运行器继续由项目宿主校验工具范围和结果；llama.cpp/vLLM的结构化输出只是传输约束，不能授予工具执行权。媒体和配置工作流统一采用原任务/尝试/外部回执语义；导入流程或ComfyUI自定义节点不自动获得安装、文件或网络权限。移动端不持有模型提供方或店铺的长期密钥，远程入口部署前另验身份与网络边界，不将当前回环API直接暴露公网。
