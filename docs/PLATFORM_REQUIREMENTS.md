### 本轮实施方向（2026-11-12）

本轮已从规划进入本地实现与联调。两个补充架构参考以后一份的最终结论为迁移方向：React + TypeScript 统一正式 Web，Python/SQLite/MCP 保持业务、任务和来源的唯一真相。CopilotKit 的开源 Surface 引擎用于受控 A2UI 1.0 组件；现有已授权模型运行器继续处理对话，不启用付费托管、第二模型路线或 Lynx 客户端。原生模块只在迁移期间复用和回退，不平行建设另一套正式业务。

用户已确认当前商品工作区效果接近目标，统一采用 AI 左侧＋业务右侧、可搜索及恢复的会话列表、五步商品清单与紧凑内容。各页面复用同一对话组件。浏览器与集成模式均取消大模块分组；集成桌面把运营台、商品、店铺管理、内容、情报、任务、能力库七个直接入口与搜索、状态合为一条顶栏，独立 Web 宽屏保留相同目的地的直接展开侧栏；手机保留底部导航。店铺管理收纳客服、补货与业务读取，Ozon/飞书及平台配置集中能力库。保留全部旧模块、深链接、原对象和草稿范围；宿主自己的原生导航不由业务插件重画。

本轮接线以已选商品的成本输入→来源与草稿版本校验→确定性计算→原产物交接→刷新与冲突恢复为验收主链；通用计算与商品绑定计算分开。真实平台写入、无人值守计划、团队远程权限和移动原生客户端仍按原阶段门槛单独验收，不因 UI 迁移开放。

## 2. 产品目标

> 经营者设定目标与边界，AI 团队围绕真实业务对象持续发现问题、组织证据、制定计划、调用已授权能力、交付产物并回读结果；人主要处理关键选择、必要审阅和异常。

平台应同时具有三个工作面：**经营工作区**处理稳定业务，**AI 任务空间**组织目标到结果，**异常与决策收件箱**集中需要人介入的事项。对话、表格、表单与生成式卡片共同完成任务。

| 层次 | 本阶段目标 | 完成判断 |
| --- | --- | --- |
| 业务价值 | 优先打通 Ozon 一店一范围及一个真实商品的研究—成本—内容—交付链 | 真实依据完整、对象明确、结果能回读；缺项如实保留 |
| AI 协作 | 从单次回答发展为目标、计划、角色、任务、产物和复验的持续协作 | 刷新、跨入口与中断后可继续同一工作，不重新描述全部背景 |
| 日常运营 | 在已启用计划内观察变化，准备可审阅建议，把异常交给合适的人 | 有触发依据、责任人、时限、处理记录与结果，而非只增加提醒 |
| 用户体验 | 用户始终知道“处理哪个对象、为什么、缺什么、下一步是什么” | 新用户和常用用户都能完成关键流程；不靠阅读长篇系统说明找动作 |
| 扩展 | 同一套能力登记和验证接入不同平台、模型、技能与渠道 | 可发现、可测试、可限权、可停用、可迁移，不能以已安装代替可用 |

首版不纳入多商家租户计费、开放插件市场、全球店铺同时上线或无限自主执行。为后续团队身份和跨机器部署保留对象归属与接口边界；当前单用户服务不能直接对小团队开放公网。

## 3. 用户、责任与工作方式

| 人的职责 | 主要工作 | 界面优先提供 |
| --- | --- | --- |
| 经营负责人 | 设目标、核预算、处理关键决策、检查结果 | 今日优先事项、目标进展、待决策、异常与效果回顾 |
| 运营成员 | 研究商品、处理店铺和内容、补资料、核回执 | 当前对象、关联任务、材料、下一步、交接与截止时间 |
| 专项协作者 | 供应链、设计、语言、客服或财务协作 | 分配给我的产物、输入约束、验收标准、反馈与重新提交 |
| 系统维护者 | 连接、模型、插件、任务故障、备份与版本 | 接入诊断、授权范围、失败原因、兼容版本、恢复与变更记录 |

首个版本可由一人承担全部职责。后续小团队协作须先实现可信身份和服务端作用域校验；界面选择“角色”或 MCP client 名称不构成权限。AI 岗位沿用现有 `organization/org.json` 的 12 个岗位及兼容别名，不新建一套竞争角色。

## 5. 目标业务能力

下面 B/A/U/X/O 编号在[验收台账](PLATFORM_BACKLOG.md)中逐项落到现有实现、页面和验收。B 为业务，A 为智能体，U 为体验，X 为扩展，O 为运行与交付。

| 需求 | 目标能力 | 关键要求 |
| --- | --- | --- |
| B01 | 统一业务对象与来源 | 店铺、市场、候选、平台商品、SKU、仓库/履约、订单、供应商、创意及客户会话关联；未知关系不猜测 |
| B02 | 店铺接入与数据就绪 | 明确授权资源、期间、分页完整性、同步水位、新鲜度和数据口径；配置与读取分开 |
| B03 | 机会发现与产品研究 | 竞品、评论、搜索和公开情报形成证据；区分信号、判断、反证、样本范围和下一步验证 |
| B04 | 供应链与商品事实 | 多供应商报价、MOQ、交期、包装、材质、样品和权利资料有版本；陈述与实测分开 |
| B05 | 经营测算与定价情景 | 同币种成本、贡献、现金和补货；比较方案、敏感因素、假设和输入缺口；跨币种另有汇率依据 |
| B06 | 商品内容与发布准备 | 真实商品事实→本地化→字段草稿→素材→规则核对→发布包；保存变更差异与审阅 |
| B07 | 内容制作与增长实验 | 参考拆解、脚本、素材、成片、变体和实验关联；生成、采用、投放和效果分别记录 |
| B08 | 库存、订单与履约 | 异常订单、可售/预留/在途口径、补货和履约计划；逐对象处理与回读 |
| B09 | 客服与售后闭环 | 接入飞书、企业微信、微信、钉钉等已选官方渠道；真实会话入口、可引用事实、回复和处理方案、人员接管、发送与结果核对 |
| B10 | 结算与经营复盘 | 订单、费用、退款、广告、物流、汇率及结算匹配；差异可解释，模型不替代账务计算 |
| B11 | 对外动作执行与回读 | 每个平台动作独立适配；操作意图、权限、幂等、提交回执、平台终态和未知处理分开 |
| B12 | 经验沉淀与知识复用 | SOP、决策理由、适用范围和有效期可查；经审阅的经验才更新策略或知识，不自动改永久记忆 |

B01 是关联模型，不是要求一次建立完整 ERP。先实现选定商品及已有来源的最小映射；B07 的广告归因、B09 的渠道、B10 的结算和 B11 的真实写入分别按接入范围落地。

## 6. 智能体工作机制

统一循环：**目标与边界 → 读取证据 → 拆解计划 → 匹配角色与能力 → 补充/审阅 → 执行 → 回读与复验 → 结果回顾**。任何阶段都可以因来源失效、资源不足或业务选择进入明确等待，不制造虚假进度。

| 需求 | 要补齐的机制 | 与现有能力的关系 |
| --- | --- | --- |
| A01 | 目标和计划 | 保存目标、范围、成功条件、优先级、截止时间及计划版本；计划步骤关联现有任务，不另建任务账本 |
| A02 | 上下文与证据组合 | 按对象、角色、问题装配最少必要资料；显示实际可读范围和未读资料，引用可定位到版本 |
| A03 | 岗位编排与产物交接 | 沿用 12 岗位契约，允许独立步骤并行，依赖未满足则等待；逐步输出可复验产物 |
| A04 | 分级自动化策略 | 用户可为具体范围启用观察、草稿和受限动作；每次执行重新核对策略、输入和预算 |
| A05 | 事件与异常处理 | 已启用的同步、数据变化、截止时间或失败触发既定计划；合并同因事件、分派责任并支持接管 |
| A06 | 模型、质量与用量 | 按任务选已配置路线，保留来源、检查结果、耗时和已知用量；不可用时说明原因，不隐式换模型 |
| A07 | 记忆、复盘与评价 | 短期任务上下文、业务事实、团队知识和实验结论分开；评价模型质量与经营效果，不互相代替 |

### 自动化等级（目标策略，尚未实现为统一策略中心）

| 等级 | 可做什么 | 如何启用和控制 |
| --- | --- | --- |
| L0 观察 | 已配置来源的读取、规则检查、排序与提醒 | 明确开启来源和规则；浏览器查看页面不自动启用任务 |
| L1 按次协作 | 明确请求的模型分析、计划、草稿和本地执行 | 复用现有显式请求和审阅；当前能力主要处于此级 |
| L2 范围内自动准备 | 事件触发模型分析、草稿、资料整理和低影响本地交接 | 先启用具体计划，限定对象/事件/模型/频率/用量/有效期；超限暂停 |
| L3 受限业务执行 | 已单独验收且被策略允许的可控外部动作 | 按店铺、动作、阈值、时限及回读规则授权；执行器实际存在才可选择 |
| L4 关键业务决策 | 新采购承诺、明显资金风险或不可逆变更等策略外事项 | 展示具体方案和影响，交给有权人员决定；不能从聊天措辞推断授权 |

同一有效策略覆盖的低风险动作无需反复索要相同授权；每次仍要产生本次对象和输入摘要，并在服务端校验。来源更新后旧动作不能重放；新动作重新计划。范围、权限、关键风险或预算改变时再审阅；只调整文案或显示布局不扩大权限。

新策略默认关闭。用户已有授权不被本文件撤销，但本次产品目标本身不授权启动无人值守模型、通知或经营写入。

## 7. 产品与界面必须遵守的原则

- 业务对象和当前工作是主线；对话用于表达意图、澄清和协作，正式产物进入对象工作区。
- 首页优先展示待处理、待补充、待决定、运行异常和已完成价值；数据未就绪时展示准备路径，演示入口明确独立。首次默认模式及老用户偏好迁移作为 U01 的新增方案单独验收。
- 稳定业务操作使用共享表格和表单；生成式界面从已登记业务组件组合，不生成任意页面代码。
- 根据现有状态给下一步；支持返回、修改、保存、继续、取消、接管和失败后的可解释恢复。
- 读取、模型调用、本地写入和平台动作分别显示；工具回执用于解释过程，不展示或伪造模型内部思维。
- 蓝白浅色、黑与中性深灰深色、跟随系统继续共用现有 UI kit 和内联资源；新组件组合复用基础组件。
- 真实与合成数据隔离，所有金额携带币种；没有汇率、期间和口径时不汇总为总利润。

## 8. 路线、成功指标与尚待决定事项

| 阶段 | 目标 | 不应被误认为完成的事项 |
| --- | --- | --- |
| M0 设计与基础合同 | 本组需求、对象/状态/权限设计、关键流程原型和验收场景 | 文档完成不代表代码完成 |
| M1 一店一商品协作闭环 | Ozon 只读验收、对象工作区、可保存的目标与人工推进计划、原任务引用、结构化产物和人工复验 | 不以本地草稿代替发布、采购、广告或结算；不新增自动派发 |
| M2 可配置的日常 AI 运营 | 在已持久计划上增加事件调度、范围内自动准备、扩展生命周期、用量与评价 | 不默认允许所有模型和外部动作 |
| M3 小团队与受控执行 | 身份权限、分派协作、已选渠道、目标服务器恢复、逐动作写入 | 必须通过真实平台与收件回读；各模块可以分批验收 |
| M4 扩大经营覆盖 | 其它平台、广告/财务/客服数据、复杂创意及更多执行器 | 多商家 SaaS 是否建设另行决定 |

M3 中身份与服务端权限是小团队远程使用的前提，不必等所有外部执行完成。用户已将飞书、企业微信、微信、钉钉列为渠道接入目标；逐渠道明确官方接口、账户与会话范围后推进，不要求等待所有业务功能完成。微信的具体账户类型仍待确定。当前可保存本项目接入选择并只读诊断既有 Hermes 适配与授权缺口，已有直接业务通知适配仍限飞书出站；不能据此宣称已有四渠道收发能力。目标服务器仍按既定后续安排推进。接入目标本身不启用真实发送或改变既有网关。

阶段切分：M1 的计划和依赖已经持久化，但由用户明确推进步骤、请求已有执行器或继续原任务；重启后提供手动恢复入口，不自动重放。M2 才按启用的 L2 策略自动派发、并行和继续。M1 的订单/库存处理可由操作者在平台人工完成后，明确请求一次只读回读并复验；平台写入与后台自动回读仍需分别按其执行/调度阶段接入。跨阶段需求的具体切片见台账。

先采基线再定业务改善目标：关键流程完成率、需重复描述对象次数、未解决缺项、产物一次验收率、来源失效拦截、重复动作数、人工处理时长、模型检查通过/人工采纳、用量和异常恢复时间。财务类结果另记真实数据分母、币种、期间和归因限制。安全与正确性门槛可先固定：越权、旧依据确认和同键重复执行的必测场景均不得出现成功写入。

后续具体实施仍需决定：首批外部动作及阈值、是否/何时开启 L2 自动计划、真实商品资料、团队成员与店铺权限、模型预算及通知/部署安排。这些均不阻止先完成界面和本地合同设计。
