# 智能跨境运营平台 · 需求与验收台账

版本：0.4 目标对齐稿；日期：2026-11-13。对应[产品目标](PLATFORM_REQUIREMENTS.md)、[业务与交互](PLATFORM_EXPERIENCE.md)及[扩展规范](PLATFORM_EXTENSIBILITY.md)。共42项需求；当前能力以[证据基线](PROJECT_ALIGNMENT.md)为准，表中“复用”不表示该需求已完整实现。三选一、独立项目资产、多设备操作、模型/工作流扩展和移动管理端均为确认目标，未以文档更新关闭验收。

P0/P1/P2 表示首版先决、高优先后续和后续扩展，不表示已发生线上事故。M0设计、M1一店一商品、M2日常自动准备、M3团队与受控执行、M4扩大覆盖；阶段是门槛，不是日期承诺。新增能力默认处于待设计/实施，涉及真实接入的验收单独记录。

### 12.1 方案复核

| 路径 | 价值 | 最可能失败的场景 | 结论 |
| --- | --- | --- | --- |
| 全面迁移到一个上游平台 | 框架、组件和生态较统一 | 未结束任务、旧版批准和未知平台回执不能保持语义，业务被迫等迁移 | 当前未证明收益覆盖迁移成本；不启动全迁移，保留可替换边界 |
| 现有系统上按能力融合 | 保留业务资产，各处独立验证和回退 | 新旧适配层分别存状态、确认和发送，形成长期双实现 | 推荐；必须绑定经营任务、唯一状态来源和旧路径退出条件 |
| 只补入口和展示 | 改动少，适合日常维护 | 找页面变快，资料、素材、批准与回执仍脱节 | 不能作为总方案；局部导航修复仍可独立交付 |

Oil UI Pro的一轮独立方案评审与主控复核一致：七个方向是能力地图，不是施工顺序。需要改为按经营任务交付，先确定对象/版本/状态来源，说明动态界面减少哪一步，给学习和触发器规定前置证据与停止条件，并把软件能力与真实资料、授权及效果分开验收。本次不打视觉分，没有重新进行最新版全站视觉或原生实操验收。
